# 当前产品契约

Concept Discovery 是面向单人长期使用的 LLM Wiki 知识闪卡网站，帮助使用者理解、联系和迁移知识。网页负责阅读、搜索、Markdown整理，以及显式发起的资料导入、整理提案审阅、轻量回想和理解写回。用户可明确提交问题，请应用依据库内资料找卡并给出有引用的应用建议。Agent仅在明确要求时查询、应用或维护知识。没有后台推荐、自动对话采集、MCP、移动端或多人功能。

## 网页与内容

网页分为知识卡列表页、新增/编辑页和详情页，统一使用纸感样式。列表提供关键词、标签、更新时间筛选和每页20条分页，筛选与页码写入URL；详情和编辑返回列表保留上下文。网页采用 React 与 Ant Design，Markdown 编辑衔接当前懒加载MDXEditor组件，默认全宽 Markdown 源码编辑，提供精简格式工具和可视化、预览切换；预览沿用服务端受限渲染，不执行原始HTML。搜索覆盖标题、正文和补充阅读。编辑页提供可选「适用任务」，复用 Markdown 中现有「适用情境」或「适用任务」章节；缺少时仅在填写并保存后新增章节。描述与正文仍为同一文档，未填写时继续按卡名检索。AI 润色只发送卡名和当前描述，建议可修改、采用或丢弃；采用仅更新草稿，保存才写入，失败保留输入。日常只要求非空标题，正文按当前语言整理自己的理解、出处、用法、边界、例子、自测问题和相关链接，不自动制造双语或空栏目。

自测问题可作为普通正文，也供轻量回想使用：有问题时先回想再展开参考解释；无问题正常阅读，不强制生成题目。回想草稿在本标签页内存保留，只有显式“保存为我的理解”才写入思源。复习排程、自动评分、提醒、命令面板、深色模式、应用内多页签及停靠面板不在第一期范围。标签、书签、关系、旧复习记录和真实知识资料不因界面精简而删除。

轻量卡和普通笔记可整篇编辑，支持项目生成的Agent追加包装。早期固定字段卡只读展示并可搜索、由Agent按块维护；无法保真编辑的原生布局提前说明。核心卡片优先显示，旧中文长文作为补充阅读保留。图片、来源、代码、表格、内链和补充阅读保留，展示转换不回写。卡片与人的理解保存在内部思源；原始资料快照、提案和知识事件位于服务私有根的wiki目录并按库身份隔离。原版网页和厂商服务不对外发布，不维护上游fork。

## 资料与知识维护

“资料与整理”接纳实际提供的Markdown/文本，不自动抓取URL；原文最多200000个Unicode字符且1MiB，完整保存，新增版本不覆盖旧快照。一次整理原文最多20000字符，原文/目录/相关卡受40000字符总预算约束，超限明确拒绝，不静默截断。用户显式发起整理后，模型先选合法已有卡，再提出至多5项有原文引用的更新；生成本身不写卡。

用户可修改整理稿、选择项目并采用；每项固定请求和op_id先持久保存，再沿受保护写入和读回流程执行。已有卡的原文及人的理解保留，自有AI区被人修改时拒绝旧更新。整体可能部分完成、冲突或未知，界面保留状态与冻结请求供核对；恢复只处理自有AI区，不覆盖人的后续内容，不承诺整批原子发布或全回滚。

问题、整理依据与“我的理解”在卡片详情读取；理解写回独立于AI更新。来源版本与逐字引用支持核对，不能自动保证解释正确。知识变化事件记录来源、提案、采用、理解保存与恢复；它不代替操作回执。详见[知识维护规则](wiki-content.md)。完整反链、lint、查询结果写回主题页和多格式提取留待后续阶段。

## 应用与Agent接口

按问题找卡使用可选服务端模型配置。登录后可在网页模型设置保存接口地址、模型和凭据，配置保存在服务端私有目录。网页和CLI共用只读 ask 命令。模型先结合最多200张卡的标题与适用任务、合计不超过12000字符的库内目录，将任务转为概念检索词；准确卡名优先匹配，证据去重后再基于限量片段选择至多5张卡片，说明理由、步骤、使用边界与资料缺口。方法请求可在具体实现资料不足时给出条件性方法；用户报告、通用知识与应用推导分开处理，不把缺失或未核对事项写成已确认事实。应用回填真实卡片链接和引用原文，材料不足时明确提示。用户提交时，问题、有限卡名及描述目录与选定正文片段发送至配置的模型服务。直接连接DeepSeek的结构化任务关闭默认思考模式；每个模型阶段遇到空白、截断、无效JSON或结构错误最多重新生成一次，仍受同一90秒期限和取消控制。引用及回答字段校验失败的候选先被丢弃，只允许基于原始合法证据重新生成一次；再次失败仍拒绝返回，模型拒绝不重试；日志仅记录阶段、次数及错误类别，不记录问题、标题、片段或凭据。网页仅在当前标签页内存保留分析结果，详情返回可恢复，刷新或退出时清除。

网页与Node CLI共用应用命令入口。日常命令为list/search/ask/polish-description/get/get-document/create/save-document/delete-document/update-block/append/recover/operation-status；CLI经stdin收JSON，stdout返回{ok:true,data}，错误写stderr并非零退出。客户端配置仅含应用地址和独立Agent令牌。初始化及迁移保留为本地管理入口，不开放HTTP。

第一期新增source-import/sources-list/source-get/wiki-propose/wiki-proposals/wiki-proposal/wiki-apply/wiki-card/wiki-understanding/wiki-events/wiki-recover；来源和提案通过独立应用命令读取，不扩展为普通概念卡目标。模型配置入口沿用原有会话设置；生成前显示目的地与模型及本次资料范围，不向调用方返回密钥。

详情页可确认删除整张卡片。删除后卡片及补充阅读退出列表、搜索和内链读取，可使用删除回执与写后版本执行 recover。整篇保存和删除要求op_id及expected_revision；块修改和追加保留expected_hash。服务端写锁、备份先行、写后读回、幂等回执、版本冲突拒绝和受保护恢复适用于所有写入。未知结果先查operation-status，不能盲目重试。预检不是内核原子CAS；原始配置仅用于维护，应避免绕过应用并发编辑。

## 运行与交付

独立应用和固定3.8.9内核通过Compose运行，仅发布应用端口。网页采用单人会话，Agent使用独立Token；内核Token和操作备份在服务端持久化。默认仅本机回环，自托管远端访问要求HTTPS反向代理；不包含厂商账号、同步或订阅。

初始化只写新目录，拒绝覆盖已有配置与数据。正式库在本机 6806 运行。[命令](../docs/agent-environment/commands.md) · [Skill](../skills/concept-discovery/SKILL.md)。

列表标签从现有Markdown标签章节/旧字段列表读取，不重写知识内容；先完成关键词、标签、日期筛选再分页。更新时间以当前正文及补充阅读中最新的内核更新时间为准，详情、排序和筛选同口径。旧`/?id=`内链继续识别，新页面使用`/cards`、`/cards/new`、`/cards/:id`及`/cards/:id/edit`，可直接打开或刷新。

从列表打开卡片后，站内返回和浏览器后退会恢复原列表的滚动位置及标题链接焦点。原卡片已离开结果时，焦点回到关键词输入框；用户在等待期间主动移走的焦点会保留。
