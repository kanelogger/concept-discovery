# 当前产品契约

Concept Discovery 是单人长期使用的桌面知识卡网站。网页负责阅读、搜索和Markdown整理。用户可明确提交问题，请应用依据库内资料找卡并给出有引用的应用建议。Agent仅在明确要求时查询、应用或维护知识。没有后台推荐、对话采集、MCP、移动端或多人功能。

## 网页与内容

网页分为知识卡列表页、新增/编辑页和详情页，统一使用纸感样式。列表提供关键词、标签、更新时间筛选和每页20条分页，筛选与页码写入URL；详情和编辑返回列表保留上下文。网页采用 React 与 Ant Design，Markdown 编辑衔接当前懒加载MDXEditor组件，默认全宽 Markdown 源码编辑，提供精简格式工具和可视化、预览切换；预览沿用服务端受限渲染，不执行原始HTML。搜索覆盖标题、正文和补充阅读。日常只要求非空标题，正文按当前语言整理自己的理解、出处、用法、边界、例子、自测问题和相关链接，不自动制造双语或空栏目。

自测是普通正文。复习、闪卡、答案揭示、评分、排程、提醒、命令面板、深色模式、应用内多页签及停靠面板已退出产品范围。标签、书签、关系、旧复习记录和真实知识资料不因界面精简而删除。

轻量卡和普通笔记可整篇编辑，支持项目生成的Agent追加包装。早期固定字段卡只读展示并可搜索、由Agent按块维护；无法保真编辑的原生布局提前说明。图片、来源、代码、表格、内链和补充阅读保留，展示转换不回写。知识源仅有内部思源内核；原版网页和厂商服务不对外发布，不维护上游fork。

## 应用与Agent接口

按问题找卡使用可选服务端模型配置。登录后可在网页模型设置保存接口地址、模型和凭据，配置保存在服务端私有目录。网页和CLI共用只读 ask 命令。模型拆分检索查询，并基于限量证据选择至多5张卡片，说明理由、步骤、使用边界与资料缺口。应用回填真实卡片链接和引用原文，材料不足时明确提示。用户提交时，问题与选定片段发送至配置的模型服务。网页仅在当前标签页内存保留分析结果，详情返回可恢复，刷新或退出时清除。

网页与Node CLI共用应用命令入口。日常命令为list/search/ask/get/get-document/create/save-document/delete-document/update-block/append/recover/operation-status；CLI经stdin收JSON，stdout返回{ok:true,data}，错误写stderr并非零退出。客户端配置仅含应用地址和独立Agent令牌。初始化及迁移保留为本地管理入口，不开放HTTP。

详情页可确认删除整张卡片。删除后卡片及补充阅读退出列表、搜索和内链读取，可使用删除回执与写后版本执行 recover。整篇保存和删除要求op_id及expected_revision；块修改和追加保留expected_hash。服务端写锁、备份先行、写后读回、幂等回执、版本冲突拒绝和受保护恢复适用于所有写入。未知结果先查operation-status，不能盲目重试。预检不是内核原子CAS；原始配置仅用于维护，应避免绕过应用并发编辑。

## 运行与交付

独立应用和固定3.8.9内核通过Compose运行，仅发布应用端口。网页采用单人会话，Agent使用独立Token；内核Token和操作备份在服务端持久化。默认仅本机回环，自托管远端访问要求HTTPS反向代理；不包含厂商账号、同步或订阅。

初始化只写新目录，拒绝覆盖已有配置与数据。正式库在本机 6806 运行。[命令](../docs/agent-environment/commands.md) · [Skill](../skills/concept-discovery/SKILL.md)。

列表标签从现有Markdown标签章节/旧字段列表读取，不重写知识内容；先完成关键词、标签、日期筛选再分页。更新时间以当前正文及补充阅读中最新的内核更新时间为准，详情、排序和筛选同口径。旧`/?id=`内链继续识别，新页面使用`/cards`、`/cards/new`、`/cards/:id`及`/cards/:id/edit`，可直接打开或刷新。

从列表打开卡片后，站内返回和浏览器后退会恢复原列表的滚动位置及标题链接焦点。原卡片已离开结果时，焦点回到关键词输入框；用户在等待期间主动移走的焦点会保留。
