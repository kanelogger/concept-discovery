# Concept Schema、CRUD 与 Dashboard 实施规格

状态：P1 待实施。本文定稿本阶段的产品与数据行为；应用框架和存储选型须在实施前记录。

## Problem Statement

用户需要在本地管理有出处的专业术语和方法论术语，并逐步补齐中文、英文内容。现有 PRD 给出了字段与页面方向，但示例中的 `status: core`、原型中的 Ready/Draft 和 Dashboard 示例数字都不能直接作为正式状态或数据契约。缺少统一规则时，Web、搜索和后续推荐容易对同一 Concept 的语言资格得出不同结果，修订也难以追溯。

## Solution

建立一份持久化 Concept 目录，使用同一套 Schema、按语言计算的资格规则和修订记录支撑本地 Card First Web。用户可创建草稿，分别补齐 `cn` / `en`，按语言浏览、搜索、编辑、归档或删除，并在 Dashboard 查看真实的目录状态。Web 只负责 Concept CRUD 与 Dashboard，不接收推荐任务，也不生成或展示 Prompt。

## User Stories

1. 作为 Concept 编辑者，我希望先录入一个有名称的词条草稿，以便日后分次补齐内容。
2. 作为 Concept 编辑者，我希望为同一 Concept 分别填写中文和英文名称，以便维护同一个概念的两种表达。
3. 作为 Concept 编辑者，我希望两种语言分别维护别名、描述和标签，以便浏览与搜索使用对应语言。
4. 作为 Concept 编辑者，我希望分别填写纯文本出处，以便说明词条来历而无需等待外部核验。
5. 作为 Concept 编辑者，我希望分别上传、预览、替换和移除中英文 WebP 配图，以便每种语言使用自己的视觉内容。
6. 作为 Concept 编辑者，我希望分别设置可选 Wiki 链接，以便读者打开对应语言的延伸阅读页面。
7. 作为 Concept 编辑者，我希望分别维护触发场景、避免场景、转化目标和 Agent 应用指引，以便逐语言补齐推荐所需内容。
8. 作为 Concept 编辑者，我希望为 Concept 设置跨语言共用的领域、意图和可选类型，以便两种语言指向同一分类。
9. 作为 Concept 编辑者，我希望类型不适用时留空，以便普通专业术语也能进入目录。
10. 作为 Concept 编辑者，我希望保存未齐备的语言版本，以便不被另一语言的进度阻塞。
11. 作为 Concept 编辑者，我希望看到每种语言缺少哪些浏览或推荐条件，以便准确补录。
12. 作为 Concept 编辑者，我希望在移除必需内容导致资格下降前看到影响，以便决定是否继续保存。
13. 作为中文读者，我希望只看到可浏览的中文内容和中文图片，以便不会误读英文内容。
14. 作为英文读者，我希望只看到可浏览的英文内容和英文图片，以便不会发生静默跨语言回退。
15. 作为读者，我希望缺少配图的可浏览 Concept 显示占位图，以便仍能阅读已发布的文字内容。
16. 作为读者，我希望有 Wiki 链接时能从详情页打开，以便继续阅读；缺失时不看到空入口。
17. 作为读者，我希望在卡片中看到名称、描述、标签和已填写的类型，以便快速判断是否要打开详情。
18. 作为目录管理员，我希望默认以卡片浏览，并可切换表格密度，以便按任务选择阅读方式。
19. 作为目录管理员，我希望搜索与筛选在结果滚动时仍可操作，以便持续缩小候选范围。
20. 作为目录管理员，我希望搜索只匹配当前语言的名称、别名、描述和标签，以便结果语言一致。
21. 作为目录管理员，我希望能在管理视图找到待补语言和已归档词条，以便继续维护或恢复。
22. 作为目录管理员，我希望先归档不再使用的 Concept，以便从浏览和后续推荐中移除而保留历史。
23. 作为目录管理员，我希望永久删除前看到二次确认和关联限制，以便避免误删。
24. 作为目录管理员，我希望看到每次修订的版本、时间、语言和变化，以便追溯文字、图片或 Wiki 链接的修改。
25. 作为目录管理员，我希望并发编辑冲突被明确提示，以便不覆盖他人或另一会话的较新修改。
26. 作为目录管理员，我希望 Dashboard 显示真实 Concept 总量与各语言资格数量，以便判断目录建设进度。
27. 作为目录管理员，我希望 Dashboard 的最近修订来自保存记录，以便区别真实变更与示例数据。
28. 作为目录管理员，我希望尚未接入的使用与评测指标明确显示未接入，以便不把示例数当真实统计。
29. 作为后续推荐能力的实现者，我希望读取与 Web 一致的语言资格结果，以便推荐池不会另算一套规则。
30. 作为本地用户，我希望重启后仍能找到已保存的 Concept、图片和修订，以便原型的内存重置行为不进入正式产品。

## Implementation Decisions

### 数据边界

- Concept Registry 是 Web 与后续推荐能力共用的唯一事实源。本阶段实现持久化 Concept、媒体引用、修订与目录查询；不复用独立原型的内存状态或复制其代码。Skillbox 仅作参考，技术选型另行记录。
- 跨语言共用字段：`id`、`lifecycle_status`、`interaction_type`、`epistemic_type`、`domains`、`intents`、`version`、`created_at`、`updated_at`。`id` 是创建时确定且不可变的唯一 slug，只接受小写字母、数字和中间连字符；重复 ID 拒绝。`interaction_type` 可空，填写时限于 `operator` / `lens` / `procedure`；`epistemic_type` 可空，填写时限于 `formal_model` / `empirical_finding` / `heuristic` / `principle` / `framework` / `law` / `bias`。空类型不显示，也不影响语言资格；已填写类型的界面标签按当前语言显示。
- `domains` / `intents` 是跨语言共用的受控代码集合，空集合允许。P1 用明确维护的代码表提供选项，初始至少包含 PRD 示例 `reasoning` / `communication` 与 `simplify` / `reduce-complexity`；后续扩展代码表不改变 Concept Schema。未知代码拒绝，不把自由输入误存为受控值。
- `locales.cn` 与 `locales.en` 各自保存 `name`、`aliases`、`description`、`cover_image`、`wiki_url`、`tags`、`trigger`、`avoid_when`、`transform`、`agent_instruction`、`source_text`。两种语言共用 Concept 身份与全局版本，不共享文案、标签、图片或 Wiki 链接；当前语言缺字段时不借用另一语言。创建时至少一个语言有非空名称，其余语言内容可留空。
- `aliases`、`tags`、`trigger`、`avoid_when`、`transform` 是该语言的文本列表；去除空白项并去重。名称、描述、Agent 应用指引和出处在资格判断前去除首尾空白；仅有空白字符不算齐备。
- `source_text` 是每种语言的单个纯文本字段。保存时仅按去除首尾空白后的非空性判断可浏览资格；不解析成结构化引用，不请求外部网站，也不核验真实性。草稿允许为空。`wiki_url` 是可选的单个绝对 HTTPS URL；填入时校验 URL 结构，缺失时隐藏延伸阅读入口，绝不代替出处文本。
- 每种语言有独立的 WebP 图片资产及引用。上传与替换要校验实际格式，提供预览；2 MB 是目标大小提示，不把原型的临时 8 MB 限制写成产品规则。草稿和可浏览 Concept 可无图并使用占位图；可推荐资格必须有本语言图片。图片引用与资产替换作为一次可恢复的保存操作处理，失败不得留下半更新记录。

### 状态与校验

| 层级 | 状态或资格 | 条件与行为 |
| --- | --- | --- |
| Concept 生命周期 | `active` | 新建默认值；语言资格按字段实时计算。 |
| Concept 生命周期 | `archived` | 保留内容、图片与修订；所有语言退出普通浏览、搜索和推荐，管理视图仍可查看与恢复。 |
| 每种语言 | 草稿 | 未满足该语言的可浏览条件；可继续保存和编辑，只在管理视图提示待补字段。 |
| 每种语言 | 可浏览（语言发布） | `active` 且该语言的 `name`、`description`、`source_text` 均为非空文本；进入该语言的普通浏览与搜索。无需另一语言齐备，也无需显式发布开关。 |
| 每种语言 | 可推荐 | 已可浏览，且该语言有 WebP 配图、至少一个非空 `trigger` 和非空 `agent_instruction`；供后续推荐接口筛选。可推荐包含可浏览资格，不是另一条互斥状态。 |

- 语言资格是从当前记录计算的结果，不存储会漂移的 Ready/Draft 标签；`status: core` 是旧示例分类，不作为生命周期或推荐资格。归档是 Concept 整体的独立生命周期，不能把一个语言的草稿状态传播到另一语言。
- 输入校验分三层：创建/保存只要求合法唯一 ID、至少一个语言名称、字段类型正确及所有已填写 URL/类型/图片有效；进入可浏览须满足该语言三个文本字段；进入可推荐再满足该语言配图、触发场景和 Agent 应用指引。保存草稿不因尚缺推荐字段失败。
- 编辑导致某语言从可推荐降为仅可浏览，或从可浏览降为草稿时，Web 先显示该语言与退出范围并请求确认；服务端保存后立即重新计算资格。另一语言若仍齐备，继续保持原有资格。归档时确认所有语言将从普通浏览和推荐中退出。
- `interaction_type`、`epistemic_type`、`domains`、`intents`、`tags`、`wiki_url`、`avoid_when`、`transform` 均不作为浏览或推荐资格的必填条件。旧 `type` 和 Core/Pack 分类不自动映射；需要迁移时另定映射表与验证案例。

### 修订与 CRUD

- 创建 Concept 形成版本 1；每次实际持久化变更使全局 `version` 加 1，并记录操作者、时间、操作、变更前后版本以及发生变化的字段。无变化的保存不增版本。编辑提交携带所见版本；版本不一致时拒绝覆盖并提示重新载入。
- 修订保留带语言前缀的字段变化，例如 `locales.cn.description` 与 `locales.en.wiki_url`，使一条记录可区分两种语言。图片变化记录语言、旧/新资产引用及可识别的摘要或元数据，不把二进制写入修订正文；历史修订引用的图片在保留历史期间仍可访问。跨语言共用字段与归档/恢复也进入同一版本序列。
- 普通删除先提供归档；永久删除仅允许已归档且无外部引用的 Concept，需二次确认。成功后永久移除记录、媒体与修订；失败或存在引用时不做部分删除。Relation 与 Usage 后续接入时必须遵守引用限制。
- 对外提供同一组持久化操作：创建、按 ID 读取、按语言查询/搜索、按版本编辑、图片上传/替换/移除、归档/恢复、永久删除、查看修订、读取 Dashboard 汇总。返回每种语言当前资格及缺失字段，Web 与未来推荐接口共用这一判定。

### Web 与 Dashboard

- Web 首页是 Concept 卡片库，Dashboard 是独立导航项；这是现有 Card First 产品原则在保留 A/B 原型中的落地选择。默认 `cn`，可切 `en`。普通卡片网格只展示当前语言可浏览且未归档的 Concept；封面缺失显示占位图，类型仅在填入时展示。详情展示同语言文案、配图、出处与可选 Wiki 链接。
- Concept 库提供卡片/表格视图切换，共用同一查询结果、搜索、状态、标签和领域筛选；搜索及筛选区在结果滚动时保持可用。管理视图可按语言查看草稿与归档条目，缺少当前语言名称时用 Concept ID 标识待补项，不跨语言填充。搜索当前语言的名称、别名、描述和标签；ID 与跨语言共用受控字段可作过滤条件。
- 创建/编辑器分隔共用字段及 `cn` / `en` 内容，逐语言展示缺失条件；支持图片预览、替换和移除、可选 Wiki URL、保存草稿与资格降级确认。两种视图都能进入相同详情、编辑和归档/删除流程。原型的备注文本域不构成已确认的正式 Schema 字段。
- Dashboard P1 的指标直接从真实数据计算，口径如下；同一 Concept 可同时计入 `cn` 与 `en`，两列不能相加当唯一 Concept 总数。

| 指标 | 数据来源与口径 |
| --- | --- |
| 活跃 Concept 总数 | Registry 中 `lifecycle_status = active` 的唯一 Concept 数。 |
| 双语均为草稿 | Registry 中活跃且 `cn` / `en` 均未达到可浏览条件的 Concept 数。 |
| `cn` / `en` 可浏览数 | Registry 中活跃且该语言满足名称、描述、出处条件的 Concept 数，分别计算。 |
| `cn` / `en` 可推荐数 | Registry 中活跃且该语言满足全部推荐条件的 Concept 数，分别计算。 |
| 归档数 | Registry 中 `lifecycle_status = archived` 的唯一 Concept 数，不混入活跃总数。 |
| 最近修订 | Revision 记录，显示真实时间、Concept、影响语言和操作；永久删除的历史不再计入。 |

- 推荐、查看、应用、忽略、无帮助等使用统计只在后续 Skill 事件接入后，从真实 Recommendation Log 汇总；离线 Eval 使用独立数据源。P1 对未接入指标显示“尚未接入”或不展示，不用原型样例数字、伪造零值或把 Web 浏览算作 Skill 使用。
- Web 没有 Recommendation Playground、推荐输入页、Apply 动作、Prompt Composer 或 Prompt 展示。此边界同样适用于 Dashboard；未来推荐接口由明确调用的 Skill 和开发用评测入口使用。

## Testing Decisions

- 主要验收缝是一套临时 Registry 数据上的真实服务读写流程，再由浏览器走同一服务的 Concept 库、编辑器、详情、修订和 Dashboard。测试外部可观察结果，避免针对内部状态计算函数编写镜像测试；这一条高层流程覆盖创建草稿、补齐中文、补齐英文、降级、归档、恢复与统计变化。
- Schema/持久化边界经公开操作验证：合法和非法 ID、重复 ID、空白出处、错误类型、未知受控代码、非 HTTPS Wiki URL、伪装成 WebP 的文件、保存失败时数据不变、版本冲突、重启后数据仍在。出处或 Wiki 网站不可访问时仍可保存合法文本与 URL，不发起外部核验。编辑中文不能修改英文，图片替换和 Wiki 变更须产生可追溯修订。
- 浏览器关键路径验证当前语言卡片/搜索/详情一致、无跨语言回退、草稿与归档过滤、卡片/表格共用结果、资格降级提示、二次删除确认，以及 Dashboard 与真实 Registry/Revision 数据一致。未来 Usage 接入前，界面不得显示示例统计或 Playground/Prompt。
- 仓库现有测试仅覆盖协作环境；没有可复用的产品测试套件。实施时沿用仓库的临时数据目录与真实读写验证规则，并为服务与浏览器添加最少的新验收入口。执行公共 `npm run check` 和新增产品验收命令；不能用当前文档校验或独立 demo 的构建结果替代产品验收。

## Out of Scope

- 推荐算法、Recommendation Playground、Prompt 生成/展示、Apply、Skill 执行和远端模型接入。
- Concept Relation、Recipe、关系编辑和关系驱动的推荐；详情中的关系区待后续阶段接入。
- Usage/Feedback 真正采集、离线 Eval 运行及其 Dashboard 汇总；P1 只规定未来指标的真实数据来源。
- 批量导入、旧 `type` 自动迁移、Core/Pack 分类迁移、云同步、多用户权限、图床/CDN、自动生图与多尺寸媒体处理。
- 生产技术栈与存储产品的指定，以及原型代码合并；实施前依据项目工作流记录选型。
