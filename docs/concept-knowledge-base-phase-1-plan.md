# 第一阶段：Concept 知识库 Web UI

状态：实施计划，尚未实施。日期：2026-09-27。

输入：用户提供的 `思维卡片系统需求调研.md`、[既有 PRD](method-system-prd-v0.1.md)、[产品契约](../specs/product-contract.md)。调研稿当前尚未纳入 Git，后续实施时按用户工作树原样读取。

## 目标

以现有本地 Registry 和 Web 系统为基础，做一个愿意持续维护、也能沿线索重新找到概念的知识库。收录范围是有可追溯名称的广义 Concept，包括理论、模型、方法和专业术语。首页以浏览和探索为主，管理操作保留在同一系统中。

第一阶段支持人工录入、关键词检索和关系探索；输入模糊现象后自动推荐 Concept 留到第二阶段。后续再接入 Agent 工作流、使用反馈与个性化。

## 实施改动

- **知识结构**：在每种语言的现有字段上增加 `questions: string[]` 和 `examples: string[]`，分别记录“问自己什么”和具体情境。两者对普通草稿可选；旧记录读取时默认为空数组。保留现有触发场景、适用边界、出处、修订和双语独立资格规则。
- **浏览体验**：卡片突出名称、一句话解释和一条“什么时候想到它”的触发场景；详情按“是什么 → 何时想到 → 诊断问题 → 适用边界 → 案例 → 相关概念 → 出处”组织。关系继续使用现有五种类型，支持从详情连续跳转，并让详情可通过 URL 打开、浏览器返回。
- **检索与编辑**：当前语言的关键词搜索加入触发场景、诊断问题和案例；匹配优先级为名称/别名、触发场景、问题/案例、描述/标签，同级按最近更新排序。不引入语义模型。编辑器将面向读者的知识字段放在前面，Agent 指令等现有字段收在高级区域；保存继续使用版本冲突检查和修订记录。
- **公开接口**：现有 Concept 创建、读取、更新接口接受并返回两个新数组；列表查询扩展搜索字段，并返回每张卡片最多两条当前语言的关系预览。无需新增数据库表或另建一份知识源。
- **首批内容**：提交一份可审阅、可导入隔离演示库的双语样本集，覆盖约束理论、五步聚焦法、瓶颈、排队论、Little 定律、在制品限制、拉动系统、流动效率、资源利用率、上下文切换、批量大小和局部优化，共 12 条。每条填写触发场景、问题、边界、案例与可追溯出处，并建立有解释价值的关系；不覆盖个人库或改写现有 80 条候选清单。[Kanban 官方指南](https://kanban.university/kanban-guide/)、[TOCICO](https://learningcenter.tocico.org/courses/Introduction-to-the-Theory-of-Constraints)和 [Little 原论文](https://pubsonline.informs.org/doi/abs/10.1287/opre.9.3.383)可作为对应条目的来源起点。

## 验收

- 在隔离数据库中完成创建、编辑、重启后读取、关系跳转和双语切换；旧记录及其修订正常读取。
- 搜索名称、别名和触发措辞均能找到对应卡片；例如与“大家都很忙但越来越慢”有关的**已录入措辞**能引导用户找到排队、约束和在制品相关条目。未录入的自由改写不承诺命中。
- 首批 12 条均有完整中英文内容、真实出处和可浏览的关系；占位出处不得作为完成证据。贴切但缺少稳定术语出处的说法放在触发描述中，只有确为同义名称时才作别名。
- 补充服务读写与浏览器关键路径回归测试，执行 `npm run test:product`、`npm run demo:build`、`npm run check` 和差异检查；按仓库工作流更新产品契约、任务证据与状态，只提交本任务相关改动。

## 已定边界

保留现有 React、Node、SQLite 架构及个人数据。第一阶段人工维护内容，不做 AI 提取、模糊语义补全或新的推荐入口。用户提供的调研文档作为方向输入；当前工作树里已有的文档和 SVG 变动在实施时保留。
