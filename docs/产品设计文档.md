# Concept Discovery 产品设计文档

状态：第一阶段代码已实施，验收证据见 [0051](../tasks/0051-web-acceptance.md)；维护者人工内容签收待完成。更新：2026-09-28。需求与阶段边界以[需求文档](需求文档.md)为准；本文说明如何实现这些需求。

## 1. 产品结构

本地 Registry 保存唯一一份 Concept、关系、图片与修订。Web 面向人提供维护和探索，后续 CLI / Skill / API / MCP 从同一知识库读取数据。

沿用现有 React / TypeScript / Vite、Node 24、SQLite 架构，见[存储决策](adr/0002-local-product-stack.md)。本地启动命令为 `npm start`，访问 `http://127.0.0.1:4173`；默认数据库为 `.local/concept-discovery.sqlite`。隔离演示库使用 `npm run demo:prepare -- --db <新数据库绝对路径>`，再设置 `CONCEPT_DB_PATH` 启动。

第一阶段只扩展知识内容和 Web 体验。现有内部 HTTP 接口继续服务 Web；对外稳定接口、认证和兼容承诺在接入阶段单独设计。

## 2. 信息架构与用户流程

主入口只有“Concept 知识库”和现有 Dashboard。搜索、筛选、详情与维护都在同一个知识库入口完成。

### 知识库首页

- 默认中文、当前语言可浏览条目、卡片视图、每页 20 条，可切换现有表格视图；顶部提供搜索、语言、状态、标签、领域筛选及新建操作。
- 普通浏览突出当前语言可浏览内容；同一视图可筛选草稿、归档和待补项。
- 卡片依次展示配图、名称、简述、一条触发场景、标签和最多两条当前语言可浏览的关联预览。缺少触发内容时不编造摘要。
- 无图片使用默认配图；未填写类型不显示类型标签。
- 保留现有每页 10 / 20 / 50 条以及卡片、表格共用查询状态的行为。

### Concept 详情

内容顺序：**是什么 → 什么时候想到它 → 问自己 → 什么时候不适用 → 案例 → 相关概念 → 出处**。空的可选区块隐藏，维护时提示缺口。

详情支持独立 URL；打开关联 Concept、刷新和浏览器返回都能恢复对应内容。详情采用 `/?concept=<id>&locale=cn`，同时保留查询、状态、标签、领域、视图和页码。打开详情及关联概念写入浏览历史，提交搜索保留列表历史；详情按 ID 独立请求，忽略过期请求结果。关闭回到保留条件的列表，恢复打开详情前的列表滚动位置。沿用当前界面基础，不为此引入第二套详情内容。

相关概念按关系类型组织，显示对应语言名称和备注；点击可浏览目标继续探索。已归档或当前语言尚不可浏览的目标显示状态，维护入口仍可处理，普通阅读不跳入空内容。语言缺失时用 ID 标识，不借用另一语言名称。

### 创建与编辑

先填写名称、简述和出处，再补充触发场景、问题、边界、案例、标签与图片。稳定 ID 在创建后不可更改；保存草稿不要求所有内容一次齐备。

面向读者的字段优先展示；现有 `transform`、`agent_instruction` 和推荐资格信息收在高级区域。两个语言分别编辑，切换语言保留未保存草稿；触发场景、问题、边界、案例和转化目标逐条编辑，保留条目内部标点与换行。关闭有修改的编辑器需确认，保存失败保留草稿。关系在条目创建后维护，避免指向未保存对象。

保存使用当前版本检查；冲突时拒绝覆盖并提示重新载入。保留修订和语言资格降级确认。活跃条目的“删除”操作先归档；归档后可恢复，永久删除遵守已有引用限制与二次确认。

### Dashboard

保留现有真实目录统计和最近修订；现有 Skill Usage 数据保持原口径，不把 Web 浏览算作 Skill 使用。第一阶段不新增推荐 Playground、Prompt 展示、模型设置或知识提取 Inbox。

## 3. Concept 数据设计

复用现有[数据与 CRUD 技术契约](../specs/concept-schema-crud-dashboard.md)。下表定义本阶段需要的数据映射，避免把草稿中的同义字段另建一套。

| 内容 | 存储方式 | 本阶段处理 |
| --- | --- | --- |
| 稳定身份、生命周期与版本 | `id`、`lifecycle_status`、`version`、创建/更新时间 | 沿用；生命周期为 `active` / `archived` |
| 分类 | 共用 `domains`、`intents`、可空的 `interaction_type` / `epistemic_type` | 沿用受控值，不强迫普通术语选近似类型 |
| 名称、别名、简述 | 每语言的 `name`、`aliases`、`description` | 沿用；`description` 承载简述，不新增重复的 `summary` |
| 何时想到 | 每语言的 `trigger: string[]` | 沿用；编辑时使用具体情境措辞 |
| 诊断问题 | 每语言的 `questions: string[]` | 新增；普通草稿可选 |
| 适用边界 | 每语言的 `avoid_when: string[]` | 沿用，记录限制与容易误用的情境 |
| 案例 | 每语言的 `examples: string[]` | 新增；普通草稿可选，案例明确为真实记录或说明性示例 |
| 标签与图片 | 每语言的 `tags`、`cover_images` | 沿用；图片为有序 WebP 资产引用 |
| 出处与延伸阅读 | 每语言的 `source_text`、可选 `wiki_url` | 沿用；出处为纯文本，链接只作延伸阅读 |
| Agent 相关内容 | 每语言的 `transform`、`agent_instruction` | 保留在高级区域，不作为第一阶段浏览门槛 |
| 概念关系 | 独立 `concept_relations` 记录 | 沿用，不嵌入另一套 `related` 数据 |

不新增独立 `heuristics`、`anti_patterns`、结构化 `sources` 或顶层案例实体；相关内容先通过现有描述、边界、案例与出处承载。字段拆分有实际维护需求后再决定。

### 双语与资格

`locales.cn`、`locales.en` 共享 Concept ID，文案、标签、图片、出处与 Wiki 链接独立。显示和搜索不跨语言回退。

- 保存：合法唯一 ID、至少一种语言有名称，已填写字段类型与值有效。
- 某语言可浏览：Concept 活跃，且该语言的名称、描述、出处文本均非空。
- 现有推荐资格：在可浏览基础上具备该语言触发场景和 Agent 指令；配图、问题、案例、类型及另一语言均不作为条件。
- 草稿是该语言缺少可浏览条件的派生结果，不增加独立审批状态机。归档作用于整个 Concept。

出处文本非空校验不代表真实性核验。个人经验填写可追溯的记录来源，知识样本另经人工审阅。

### 兼容与持久化

新增数组接受字符串列表，去除空白项并去重。创建、读取、更新接口及修订记录都需支持新字段。旧记录缺少字段时按空数组读取，旧修订保持原样；部分更新不清空未提供字段。无需新增表或复制知识库。

延续版本冲突检查、写入事务及修订语义；失败不留下部分写入。保持现有个人数据和资产引用，样本只导入显式指定的隔离库。

## 4. 关系设计

沿用[关系技术契约](../specs/concept-relations.md)的五种关系，不采用新草稿中的八种关系枚举。

| 类型 | 阅读含义 | 方向 |
| --- | --- | --- |
| `related_to` | 相关概念 | 对称 |
| `often_used_with` | 常配合使用 | 对称 |
| `contrasts_with` | 对照或相反视角 | 对称 |
| `extends` | 对另一个概念的扩展 | 有向 |
| `part_of` | 属于另一个概念的一部分 | 有向 |

关系必须有两个不同的现存端点，禁止同类型重复关系；中文与英文备注独立维护。显示有向关系时根据当前端点使用正向或反向文案。关系用于解释具体关联，不把“常配合使用”写成等价或因果。

新增卡片关系预览和详情连续跳转；不建设全屏图谱，不增加 Recipe 或组合执行流程。

## 5. 搜索设计

列表关键词搜索使用当前语言字段匹配，不依赖模型或向量库。输入框只保留草稿；回车或点击“搜索”后去除首尾空白并提交查询。清空按钮清除输入及已应用关键词；“重置”同时清除关键词、标签、领域并恢复可浏览状态。每次非空提交还会打开侧边抽屉，请求 DeepSeek 从当前语言可浏览 Concept 中选出最多三条并给出理由。抽屉具有加载、无结果与失败状态；点击推荐卡片打开 Concept 详情时抽屉保持打开，关闭详情后返回抽屉；只有“关闭推荐”按钮收起抽屉，收起后不丢失关键词结果。

查询去除首尾空白、忽略大小写，在单个字段或单个列表项内做子串匹配。按最高命中优先级排序，同级按更新时间降序、ID 升序；空查询也按更新时间和 ID 排序：

1. 名称、别名。
2. 触发场景。
3. 诊断问题、案例。
4. 描述、标签。

筛选继续使用现有语言、生命周期、领域与标签规则；草稿和归档只在明确的维护筛选中展示。列表接口扩展搜索字段，通过 `include=relation_preview` 按需批量返回最多两条活跃且当前语言可浏览的关联目标。按关系 ID 排序，同目标去重；预览不持久化、不进入修订和推荐输入。

例如，“大家都很忙但越来越慢”出现在某条触发描述中时，关键词结果应能找到它；未录入的自由改写不承诺关键词命中。模型抽屉可从已有条目中推荐相关概念，不能编造 ID；DeepSeek 不可用或返回空时，关键词结果仍可查看。

## 6. 首批内容与验收用例

约 12 条双语样本：约束理论、五步聚焦法、瓶颈、排队论、Little 定律、在制品限制、拉动系统、流动效率、资源利用率、上下文切换、批量大小、局部优化。

每条补齐名称、别名（确有时）、简述、触发场景、问题、边界、案例及可追溯出处，并建立能解释差异或配合方式的关系。需求中的 Utilization Trap 是目标体验示意；未核实稳定名称前，用作现象描述，不自动设为正式条目或别名。

样本以版本化数据交付，使用隔离数据库验收。样本见 `data/examples/knowledge-base-v1.json`，包含 12 条双语 Concept 和 12 条关系；每条的来源标题、URL、查阅日期保存在出处字段。实施 Agent 已查阅来源并对照双语内容，维护者人工内容签收仍待完成，核验记录见 [0050](../tasks/0050-knowledge-samples.md)。旧清洗稿依赖的 `daily-knowledge(1).md` 未提供，其条目不能被视为已核验数据。

| 验收路径 | 必须观察到的结果 |
| --- | --- |
| 新建与保存 | 两个新数组可写入，重启后仍可读取；旧数据与修订兼容 |
| 搜索 | 名称、别名、触发场景、问题、案例分别命中，排序与当前语言一致 |
| 浏览关系 | 卡片预览、详情跳转、直接 URL、刷新和浏览器返回可用 |
| 编辑保护 | 版本冲突不覆盖，归档/恢复/受保护删除继续有效 |
| 双语阅读 | 不混用另一语言文本或图片；缺失状态清楚 |
| 内容质量 | 样本出处真实、关系含义明确，不以占位文本通过验收 |

实施时补充有回归价值的服务与浏览器关键路径测试，执行 `npm run test:product`、`npm run demo:build`、`npm run check`；实际执行结果见 [0051](../tasks/0051-web-acceptance.md)。
