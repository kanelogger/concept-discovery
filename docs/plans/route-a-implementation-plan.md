# 路线 A 重构实施方案：先定位加载耗时，再按实测改造

**第一轮交付一张慢页面的分段耗时表和一项能独立发布的提速改动。** 先在现有思源站点复现读者的等待，判断时间花在建立连接、会话验证、资源加载还是业务查询，再用相同条件测出内容提前了多少毫秒出现。

长期目标沿用同目录参考稿 `route-a-refactor-design.md` 的路线 A。作者通过 Git 维护 `raw/`，宿主预编译正文、搜索索引、图谱和图鉴，单个 Node 24 应用容器提供阅读、搜索和分享。前端沿用 React 19、esbuild 和纸感主题。正式迁移时撤下网页内容维护和四小时导出，保留站主登录、会话及分享管理。以下数字分别注明离线估算或验收目标；生产基线待测。[现行产品契约](../../specs/product-contract.md)

## 一、先测实际慢页面

以读者遇到等待的网址和登录状态为主样本，另用已登录的 `/cards` 首屏 20 条结果作对照。每组在同一设备、浏览器、网络和站点版本做 **5 次冷访和 5 次正常二访**。每对测量从空 HTTP 缓存开始，保留有效会话并启用缓存；二访在同一浏览器会话中新开标签页输入原地址。同时记录是否复用连接。浏览器关闭请求拦截，强制刷新与 SPA 返回另记。

从开始导航计时，直到首批卡片或目标正文可读。瀑布按时间顺序记录 DNS、TCP、TLS、HTML 首字节、JS/CSS 下载与执行、`/api/session`、业务 API 和数据返回后的渲染。报告每次的内容可读时间、FCP、LCP、实际编码字节及各组中位数。并行请求按关键路径归因。代理等待明显时，再用同一请求的 Nginx 和应用记录区分代理子请求、Node 就绪检查和业务处理。配置中的 2 秒和 4 秒是超时上限。交付冷访/二访对照表和脱敏瀑布摘要，移除 Cookie、认证头、分享凭证及私人正文。[旧代理配置](../../deploy/nginx-lifecycle-gate.conf) · [HTTP 入口](../../server/app.mjs)

已有本机产物的入口静态依赖和 CSS 共 **743,599 字节**，计入列表分包后为 **1,237,493 字节**，逐文件用 Brotli 级别 9 离线压缩后合计 **374,062 字节**。线上是否已有压缩、浏览器实际下载哪些文件及下载是否主导等待，以本轮实测为准。现有性能夹具使用回环地址、本地认证和合成内核，适合对照列表或图谱渲染。[前端构建](../../scripts/build-web.mjs) · [已有性能夹具](../../tests/performance/cards-graph.mjs)

### 按耗时最长的环节选择首轮改动

| 实测瓶颈 | 可单独发布的改动 | 复测证据 |
| --- | --- | --- |
| 程序资源下载或二访重复传输 | 给入口和分包加内容哈希，构建 Brotli/Gzip 版本。`server/ui-assets.mjs` 在服务启动时读取清单，`web/index.html` 由服务端按清单注入 JS/CSS 路径。仅清单内带哈希的纯程序资源使用长期缓存。 | 核对冷访编码与字节、正常二访缓存命中，验证旧标签页仍可载入先前版本的分包。 |
| 维护就绪检查 | 分别计量 Nginx 的 `auth_request` 与应用内部检查。若收益明确，仅给清单内的公开程序资源免去这两次检查。私有附件、HTML、API、分享正文和封面继续按原权限处理。 | 在真实代理夹具中关闭业务入口，核实仅允许的程序文件仍可读取；未知路径和私有对象继续受限。 |
| 验证会话或业务查询 | 若慢在 `/api/session`，首次渲染复用服务端已验证的会话，保留过期和撤销检查。若慢在列表、场景或图谱，优先为该查询交付经过新旧对照的 SQLite 读取或预计算视图。 | 分别比较请求数、接口首字节和内容可读时间，复测会话过期、撤销及迟到响应。 |

每次改动后重复同组测量，报告修改前后中位数和样本范围。若主要等待来自公网建连或 TLS，优先定位对应链路并复测，再排应用改动。

**内容库的最小模型**

- `cards` 保存稳定 slug、公开 ID、标题、排序时间、修订、描述、正文 Markdown、安全 HTML、自测与章节。另存有序补读、标签、学科、原文关联和活动状态。旧卡的公开 API `id` 沿用既有文档 ID；经核实从未有旧身份的新卡用稳定 slug。发布后保留其公开身份。各命名空间碰撞时拒绝编译。为合法 slug `new` 生成并保持 `/?id=new` 的详情地址，使旧书签 `/cards/new` 仍回列表。
- 身份表解析 slug、旧文档 ID、历史概念别名、补读 ID 和块 ID，指向卡/补读及锚点。旧图谱的 `cd-ref-*` 锚名包含目标 ID 的摘要，改用 slug 时为旧出处保留锚名。映射在冻结副本中按归属核实，冲突或丢失的旧目标列为差异。保留 schema 1 的字段、`sections` 和旧关系供 CLI `get` 使用。迁移时将原接口读回的更新时间（含补读变更）写入以稳定公开 ID 为键的版本化元数据清单，使用北京时间 14 位格式。此后作者在卡片或补读发生实质变化时随原稿更新该值。编译器从清单取值，缺失或格式错误时指出对应卡；无 Git 历史、文件时间变化、仅调整 YAML 排版或重编译时，原更新时间和排序一致。
- `sources` 以快照 ID 查原文，保留逻辑来源 ID、版本、作者、出处、原文及校验值。每次发布把新版本加入持久的版本档案，再构建只读库；已发版本继续可重建。历史提案、事件保留原 ID 和记录。发布输入缺失、归属错误、同 ID 不同内容时终止。普通发布不得静默丢弃历史。
- `assets` 保存受管相对路径、旧资源名、完整内容哈希、类型和活动引用方。按哈希去重，原图表、补读和共享引用均可回读。只分发清单内且有活动引用的二进制，保留既有 `/assets/…` 映射。发布目录和 SQLite 文件不挂成公网静态根。

**编译顺序。** 先用 `loadRawTree` 校验并分配全库身份，再用 `compileRawCard` 解析 Wiki 与相对链接，通过现有渲染器生成安全 HTML、章节和可定位的引用原句。图谱按活动主卡建节点，保留孤立卡，合并同向重复引用并保留各出处；学科、目录成员和旧结构化关系各自独立。图鉴沿用精选、说明、类目及学科顺序、空学科和缺失/重复目录诊断，将当前限定原生 ID 的解析改为查身份表。预生成两种视图的 JSON 与校验值。构建后校验外键、完整性、引用与资源，再封存发布清单。[安全渲染及引用](../../server/card-references.mjs) · [图谱](../../server/knowledge-graph.mjs) · [场景图鉴](../../lib/scenario-atlas.mjs)

**中文搜索。** 保留当前按空白拆词、任一词命中、字面子串匹配、补读命中归父卡的规则。使用 FTS5 trigram 产生三字符及以上词的候选，每个候选按原字段/块核对；一、二字符词直接走绑定参数的字面子串查询。在同一套规则下处理英文大小写、引号、百分号与下划线。词命中集合取并集，然后按各命令原有排序、limit 和分页返回。列表按更新时间和公开 ID 倒序；展开标签时统计当前关键词、日期条件下的全量标签。用“刀”“剃刀”“姆剃刀”、仅补读命中、多词和特殊字符做新旧差分。在目标 Node 镜像实际建 FTS5 表并查询后才采用该路径。[列表匹配](../../lib/library-scope.mjs) · [CLI 搜索](../../lib/knowledge.mjs)

## 三、切换读取层，保住外部契约

在 `server/app.mjs` 的读取分派处引入只读内容接口。旧实现与 SQLite 实现各自启动，测试从相同 HTTP/CLI 入口比较。分享路由现用 `validBlockID` 拒绝 slug，且创建时会比对 `card.id`。改为先解析到活动主卡的稳定公开 ID，再读详情、取受权图片、生成 `shareable` 标记及访问分享记录。分享、待删和永久删除记录中的 `card_id` 永久等于该卡首次公开的 API `id`。旧卡使用核实的思源文档 ID，无旧身份的新卡使用首次发布的 slug。改名或更换 slug 时仅更新别名映射，原分享主键、撤销记录和删除决定继续生效。新卡可用 slug 创建、读取、升级预览和撤销分享。把 `fail`、哈希等通用工具从思源模块独立出来，按调用关系逐步停用旧实现。[HTTP 入口](../../server/app.mjs) · [分享路由](../../server/card-share-http.mjs) · [分享存储](../../server/card-share-store.mjs)

| 调用方 | 必须保持的行为与验收样例 |
| --- | --- |
| 网页和 Agent CLI | 保留十个 POST 命令 `list`、`search`、`get`、`get-document`、`sources-list`、`source-get`、`wiki-card`、`wiki-proposals`、`wiki-proposal`、`wiki-events`。逐个比对响应字段、空结果、错误码、分页和 CLI stdout/stderr/退出码。`get-document` 返回同一版的自测与只读标记，Agent 令牌只用于只读命令。`GET /api/status` 维持 `data.readOnly: true`。[命令白名单](../../lib/read-commands.mjs) |
| 旧书签与阅读位置 | slug、`/cards/<旧ID>`、`/?id=<块或文档ID>`、补读、`/cards/new`、`/cards/<ID>/edit`、查询参数与片段进入正确卡和位置。点图谱出处、图鉴卡堆或 `/wiki?source=<快照ID>` 后，前进、后退能恢复选择、焦点和滚动。 |
| 站主与访客 | 保留回环 local 和 HTTPS required 两种模式、Host/Origin、登录后返回及改密撤销。冻结分享继续支持 `/share#凭证`、`/share/<预览ID>#凭证`、对应封面和可选微信签名。原卡编辑不改旧分享；归档暂停，彻底删除或撤销后拒绝，从旧快照恢复也不能重新读到。验证创建时只含主卡正文和允许的位图，沿用 48 个、总计 6 MiB 上限。 |

**缓存规则直接按访问权限设置。**

| 响应 | 拟采用的策略 |
| --- | --- |
| 仅包含程序的带哈希 JS/CSS、字体 | `public, max-age=31536000, immutable`，清单随版本加载一次；保留一段部署重叠期供已打开标签页载入旧分包。构建时生成 Brotli/Gzip，协商编码、支持 identity，合并 `Vary: Accept-Encoding` 与现有 Vary 字段。 |
| 登录页、带初始数据的 HTML、命令 POST、旧路径私有附件、可撤销的分享正文/预览/专属封面 | `no-store`。每次先核实权限与活动状态。分享路径的 GET 和 HEAD 一致拒绝已撤销对象。附件保留类型限制和沙箱头。 |
| 带内容哈希的私有图片 | `private, no-cache` 加 ETag。先验证会话与当前活动引用，再匹配 `If-None-Match`。未变返回无正文的 `304`，已退出返回 `401`，已无活动引用返回 `404`。保留卡共用同一图片时仍可读取。拒绝响应使用 `no-store`。 |
| 图谱及图鉴的私有 GET | `private, no-cache`，先鉴权再判断 `If-None-Match`。ETag 区分视图、可见内容版本及返回表示；已退出、不可见或已撤销时返回对应拒绝响应。 |

**后续前端瘦身。** 在第一轮改动基础上沿用 React、现有 esbuild 分包、纸感 CSS 和路由状态测试。按首屏瀑布在鉴权后只内联当前列表页或当前卡的初始数据；用安全 JSON 序列化转义 HTML 边界，沿用 CSP，公开分享单独生成最小页面。图谱和大型原文按需读取。依次替换列表筛选、阅读/回想、图鉴、资料与登录/分享组件，最后移除 AntD、图标包和对应 nonce 适配。保留图谱动态导入，通过构建依赖清单验证首屏没有引入 D3；只在分包测量支持时进一步拆 D3。浏览器覆盖中文输入法、键盘、目录锚点、迟到响应及退出后清除旧内容。[路由](../../web/routes.mjs) · [现有浏览器回归](../../tests/browser)

| 迁移准备 · 内容对账 | 先用隔离旧实例与合成样本固定接口、权限和路由响应。正式切换前，在站主授权的窗口冻结内容维护和发布，保留分享撤销能力；结算批次、原稿冲突、归档、待删与权威删除决定。在独立副本导出清单，逐项解释线上与仓库差异。 | 对得上库身份、Git 版本、活动/隐藏集合、块、补读、引用、图片、历史资料及分享状态。缺少原稿或归档标记的旧卡要找回正文、补读、附件和原 ID，或记录站主处置；归属不明或队列未结算，继续沿用原栈。 |

| 2 · 影子服务 | Node 独立运行 SQLite 后端，复用现有前端、认证和分享接口。比较两个本地服务的十个命令、图鉴、图谱、图片、书签、可见集合及拒绝结果。 | 允许差异仅限已批准的维护入口退役或表现优化。影子环境使用隔离认证库；验证归档、撤销、保留卡与共用图片。对有转发素材、无素材和已删的卡分别验证站主建议、新建分享和旧分享升级。 |

| 4 · 单容器切流 | 修改 `scripts/service-start.mjs`、`server/main.mjs`、Dockerfile、Compose 及开发入口，消除内核初始化和 socket 依赖。应用只读挂载经校验的内容版本及与之匹配的分享素材目录，独立挂载认证卷；按构建阶段收窄 `.dockerignore` 放行项。 | 按下方顺序切换并演练回退。读回健康、旧正文、有效/撤销分享和不可见目标后，再停用旧维护部署。收尾更新产品契约、项目清单、CLI/Skill 说明及测试入口。 |

### 正式切换、删除和回退

1. **切流。** 站主选择单人发布窗口，关闭公网业务入口、排空请求，结算并停止旧栈写入与定时导出。核实原稿、历史、归档、已有权威删除决定和认证状态，留存一致的完整冷备。宿主将候选内容包写入新目录，校验清单后按同一内容版本只读挂载。用正式 Host 与协议从回环读回代表性页面、分享和拒绝样本，再原子切换代理上游并替换旧 socket 门禁。异常时维持维护页。[旧代理配置](../../deploy/nginx-lifecycle-gate.conf)
2. **日常发布和删除。** 由站主逐次发布已核准的内容。每次开放入口或回退前，都用当前批准的活动/归档清单和冷备之外的最新删除记录核对候选包；若旧包仍能展示受限卡，维持维护页。用删除前构建的旧包验收这一点。归档保留恢复身份；永久删除以稳定公开 ID 记入保存在冷备之外的删除记录。收缩可见范围时关闭业务入口。归档期间暂停原分享，恢复卡片后仍须核对其撤销状态。永久删除时作废相关分享，清理认证库中的冻结正文、专属封面及数据页/WAL。核对各在线发布目录、独占附件、原稿副本与分享素材，从存储和 HTTP 两端读回后开放。保留卡所用的共享图片继续可读，纯程序分包可保留到版本重叠期结束。旧思源完整私有根移出服务宿主，只作离线冷备；交割前仍在线的旧副本按既有规程清理并读回。
3. **回退。** SQLite 正式接管后，使用上一兼容程序镜像、当前核准的内容包及最新认证库。逐项验证归档卡 A、已删卡 B、保留卡 C、旧分享和 B/C 共用图片；缺少兼容程序或读回失败时保持维护页，修复候选版本。思源冷备仅用于离线核对，不安排向旧栈反向重放或切回。若须从冷备恢复认证库，按现有规程撤销备份中的会话与分享，再核对最新删除记录。[旧系统维护与冷备规程](../../docs/agent-environment/commands.md#站主卡片维护与冷备门禁)
