# 路线 A 重构实施方案

**建议先交付一个能与旧站逐项对照的 SQLite 阅读服务，再拆思源。** 目标是让作者在 Git 中维护 `raw/`，让读者继续用原书签、搜索和分享读到同一份内容。服务器只运行一个 Node 24 应用容器，沿用宿主 HTTPS 代理。正文解析、引用抽取、图谱和图鉴计算都移到构建期。

本文将同目录的 `route-a-refactor-design.md` 落到现有实现。沿用任务 0068 的 React 19、esbuild 和纸感主题选择。产品上的主要取舍是撤下网页新增、编辑、归档、恢复、待删提醒和四小时导出，转由作者修改原稿并发布。站主登录、会话管理、创建与撤销分享继续生效。本次交付为设计；上线前由站主确认在线维护退役窗口和生产基线。以下性能数字均为拟验收目标。现行行为以[产品契约](../../specs/product-contract.md)为准。

## 二、一个内容版本，两类存储

| 数据及位置 | 写入者、用途和寿命 |
| --- | --- |
| `raw/`，以及一次性迁入的私有历史基线 | 作者在 Git 修改卡片、附件、补读和场景目录。将核实的场景目录沿用普通卡的 `article.md` 和原身份。私有基线保留已发原文版本、提案、事件与兼容映射；按原库身份封存并受控备份。 |
| 版本化的只读发布目录 | 构建器从指定 Git 提交及指定私有基线生成 `knowledge.sqlite`、附件、前端分包和清单。发布时配套安装分享标题、摘要与 PNG 封面，按 raw ID 和卡名核验素材目录。清单记录输入版本、格式版本及各文件 SHA-256。整组安装到新目录，校验后启动新进程；每个进程只读一版，普通构建失败继续服务上一版。 |
| 持久卷上的 `auth.sqlite` | 站主、会话、分享令牌、代次、冻结正文/图片、预览及撤销状态沿用当前实例。内容发布不覆盖这个库。影子环境使用隔离副本。 |

**内容库的最小模型**

- `cards` 保存稳定 slug、公开 ID、标题、排序时间、修订、描述、正文 Markdown、安全 HTML、自测与章节。另存有序补读、标签、学科、原文关联和活动状态。旧卡的公开 API `id` 沿用既有文档 ID；经核实从未有旧身份的新卡用稳定 slug。发布后保留其公开身份。各命名空间碰撞时拒绝编译。为合法 slug `new` 生成并保持 `/?id=new` 的详情地址，使旧书签 `/cards/new` 仍回列表。
- 身份表解析 slug、旧文档 ID、历史概念别名、补读 ID 和块 ID，指向卡/补读及锚点。旧图谱的 `cd-ref-*` 锚名包含目标 ID 的摘要，改用 slug 时为旧出处保留锚名。映射在冻结副本中按归属核实，冲突或丢失的旧目标列为差异。保留 schema 1 的字段、`sections` 和旧关系供 CLI `get` 使用。旧卡更新时间取原接口读回值，含补读变更；之后根据相邻 Git 版本中卡及补读的实质变化记录更新时间，保留 14 位格式与北京时间筛选。整库重编译须保持未变卡的时间、修订和排序。
- `sources` 以快照 ID 查原文，保留逻辑来源 ID、版本、作者、出处、原文及校验值。每次发布把新版本加入持久的版本档案，再构建只读库；已发版本继续可重建。历史提案、事件保留原 ID 和记录。发布输入缺失、归属错误、同 ID 不同内容时终止。普通发布不得静默丢弃历史。
- `assets` 保存受管相对路径、旧资源名、完整内容哈希、类型和活动引用方。按哈希去重，原图表、补读和共享引用均可回读。只分发清单内且有活动引用的二进制，保留既有 `/assets/…` 映射。发布目录和 SQLite 文件不挂成公网静态根。

**编译顺序。** 先用 `loadRawTree` 校验并分配全库身份，再用 `compileRawCard` 解析 Wiki 与相对链接，通过现有渲染器生成安全 HTML、章节和可定位的引用原句。图谱按活动主卡建节点，保留孤立卡，合并同向重复引用并保留各出处；学科、目录成员和旧结构化关系各自独立。图鉴沿用精选、说明、类目及学科顺序、空学科和缺失/重复目录诊断，将当前限定原生 ID 的解析改为查身份表。预生成两种视图的 JSON 与校验值。构建后校验外键、完整性、引用与资源，再封存发布清单。[安全渲染及引用](../../server/card-references.mjs) · [图谱](../../server/knowledge-graph.mjs) · [场景图鉴](../../lib/scenario-atlas.mjs)

**中文搜索。** 保留当前按空白拆词、任一词命中、字面子串匹配、补读命中归父卡的规则。使用 FTS5 trigram 产生三字符及以上词的候选，每个候选按原字段/块核对；一、二字符词直接走绑定参数的字面子串查询。在同一套规则下处理英文大小写、引号、百分号与下划线。词命中集合取并集，然后按各命令原有排序、limit 和分页返回。列表按更新时间和公开 ID 倒序；展开标签时统计当前关键词、日期条件下的全量标签。用“刀”“剃刀”“姆剃刀”、仅补读命中、多词和特殊字符做新旧差分。在目标 Node 镜像实际建 FTS5 表并查询后才采用该路径。[列表匹配](../../lib/library-scope.mjs) · [CLI 搜索](../../lib/knowledge.mjs)

## 三、切换读取层，保住外部契约

在 `server/app.mjs` 的读取分派处引入只读内容接口。旧实现与 SQLite 实现各自启动，测试从相同 HTTP/CLI 入口比较。分享路由现用 `validBlockID` 拒绝 slug，且创建时会比对 `card.id`。改为先解析到活动主卡的稳定公开 ID，再读详情、取受权图片、生成 `shareable` 标记及访问分享记录。旧 ID 和别名共用同一记录，新卡可用 slug 创建、读取、升级预览和撤销分享。把 `fail`、哈希等通用工具从思源模块独立出来，按调用关系逐步停用旧实现。[HTTP 入口](../../server/app.mjs) · [分享路由](../../server/card-share-http.mjs) · [分享存储](../../server/card-share-store.mjs)

| 调用方 | 必须保持的行为与验收样例 |
| --- | --- |
| 网页和 Agent CLI | 保留十个 POST 命令 `list`、`search`、`get`、`get-document`、`sources-list`、`source-get`、`wiki-card`、`wiki-proposals`、`wiki-proposal`、`wiki-events`。逐个比对响应字段、空结果、错误码、分页和 CLI stdout/stderr/退出码。`get-document` 返回同一版的自测与只读标记，Agent 令牌只用于只读命令。`GET /api/status` 维持 `data.readOnly: true`。[命令白名单](../../lib/read-commands.mjs) |
| 旧书签与阅读位置 | slug、`/cards/<旧ID>`、`/?id=<块或文档ID>`、补读、`/cards/new`、`/cards/<ID>/edit`、查询参数与片段进入正确卡和位置。点图谱出处、图鉴卡堆或 `/wiki?source=<快照ID>` 后，前进、后退能恢复选择、焦点和滚动。 |
| 站主与访客 | 保留回环 local 和 HTTPS required 两种模式、Host/Origin、登录后返回及改密撤销。冻结分享继续支持 `/share#凭证`、`/share/<预览ID>#凭证`、对应封面和可选微信签名。原卡编辑不改旧分享；归档暂停，彻底删除或撤销后拒绝，从旧快照恢复也不能重新读到。验证创建时只含主卡正文和允许的位图，沿用 48 个、总计 6 MiB 上限。 |

**缓存规则直接按访问权限设置。**

| 响应 | 拟采用的策略 |
| --- | --- |
| 仅包含程序的带哈希 JS/CSS、字体 | `public, max-age=31536000, immutable`，清单随版本加载一次；保留一段部署重叠期供已打开标签页载入旧分包。构建时生成 Brotli/Gzip，协商编码、支持 identity，合并 `Vary: Accept-Encoding` 与现有 Vary 字段。 |
| 登录页、带初始数据的 HTML、命令 POST、私有附件、可撤销的分享正文/预览/专属封面 | `no-store`。每次先核实权限与活动状态。分享路径的 GET 和 HEAD 一致拒绝已撤销对象。附件保留类型限制和沙箱头。 |
| 图谱及图鉴的私有 GET | `private, no-cache`，先鉴权再判断 `If-None-Match`。ETag 区分视图、可见内容版本及返回表示；已退出、不可见或已撤销时返回对应拒绝响应。 |

**前端先换数据，再减体积。** 沿用 React、现有 esbuild 分包、纸感 CSS 和路由状态测试。先让服务端在鉴权后只内联当前列表页或当前卡的初始数据；用安全 JSON 序列化转义 HTML 边界，沿用 CSP，公开分享单独生成最小页面。图谱和大型原文按需读取。依次替换列表筛选、阅读/回想、图鉴、资料与登录/分享组件，最后移除 AntD、图标包和对应 nonce 适配。保留图谱动态导入，通过构建依赖清单验证首屏没有引入 D3；只在分包测量支持时进一步拆 D3。浏览器覆盖中文输入法、键盘、目录锚点、迟到响应及退出后清除旧内容。[路由](../../web/routes.mjs) · [现有浏览器回归](../../tests/browser)

## 四、交付顺序与停止条件

| 阶段 | 可独立交付的结果 | 通过条件与失败处理 |
| --- | --- | --- |
| 0 · 建立基线 | 先用隔离旧实例与合成样本固定接口、权限和路由响应。正式切换前，在站主授权的窗口冻结内容维护和发布，保留分享撤销能力；结算批次、原稿冲突、归档、待删与权威删除决定。在独立副本导出清单，逐项解释线上与仓库差异。 | 对得上库身份、Git 版本、活动/隐藏集合、块、补读、引用、图片、历史资料及分享状态。缺少原稿或归档标记的旧卡要找回正文、补读、附件和原 ID，或记录站主处置；归属不明或队列未结算，继续沿用原栈。 |
| 1 · 离线编译 | 拟新增 `scripts/build-content.mjs`（npm 脚本 `build:content`）与 `lib/content-store.mjs`，接受显式原稿目录、历史基线和新输出目录。先用一张旧卡、一张无旧 ID 卡、共用图片、补读与两版原文贯通编译和只读查询，再覆盖整库。 | 同一输入两次编译，逻辑清单与可见内容一致；有意制造坏引用、身份碰撞、历史版本缺失或残缺附件，构建应失败且旧版本仍可读。 |
| 2 · 影子服务 | Node 独立运行 SQLite 后端，复用现有前端、认证和分享接口。比较两个本地服务的十个命令、图鉴、图谱、图片、书签、可见集合及拒绝结果。 | 允许差异仅限已批准的维护入口退役或表现优化。影子环境使用隔离认证库；验证归档、撤销、保留卡与共用图片。对有转发素材、无素材和已删的卡分别验证站主建议、新建分享和旧分享升级。 |
| 3 · 轻量前端 | 交付有哈希的入口文件、预压缩资源、首屏数据和精简组件。分别核对登录、列表、阅读/回想、图鉴、图谱、资料和分享。 | 为浏览器测试增加“合成 raw → 编译 → 单容器”夹具，切换 `tests/browser/fixtures.mjs` 的服务提供者；旧对照组固定旧提交和旧 Compose。替换依赖 AntD 类名的断言，按可见结果检查性能与交互。 |
| 4 · 单容器切流 | 修改 `scripts/service-start.mjs`、`server/main.mjs`、Dockerfile、Compose 及开发入口，消除内核初始化和 socket 依赖。应用只读挂载经校验的内容版本及与之匹配的分享素材目录，独立挂载认证卷；按构建阶段收窄 `.dockerignore` 放行项。 | 按下方顺序切换并演练回退。读回健康、旧正文、有效/撤销分享和不可见目标后，再停用旧维护部署。收尾更新产品契约、项目清单、CLI/Skill 说明及测试入口。 |

### 正式切换、删除和回退

1. **切流。** 旧 Nginx 的 `auth_request` 依赖维护 socket 提供的 `/api/readiness`。先安装独立于旧服务的默认关闸配置。在同一宿主发布锁下关公网、排空请求、停止写入，留存一致的私有根备份和镜像/配置；在冷备以外保留控制库和已核验的账本头。核对最后一批 Git、活动/归档清单、删除决定与认证状态，启动回环上的单容器候选。用代理将要使用的 Host 和协议读回私有页面、活跃分享和拒绝样本。全部一致才原子启用新代理配置，替换旧 socket 门禁。中断、缺少清单或版本落后时维持关闸，重启也须重新核实。[旧代理配置](../../deploy/nginx-lifecycle-gate.conf)
2. **谁决定可见。** 把当前批准的内容版本、活动/归档身份和已核验的不可逆删除决定放在独立于发布目录及冷备的受保护发布记录中。日常发布、归档、永久删除与回退共用发布锁。归档可以恢复；永久删除须显式指明稳定 ID。从 Git 移走原稿但未说明归属时拒绝发布。涉及可见性收缩时先关入口、排空请求，再登记决定。开闸前在锁内再次核对权威头与当前发布版本，条件变更即拒绝激活。演练早先的构建晚返回、验收后新增删除决定两种竞态，确认旧包均不能上线。
3. **永久删除做到存储读回。** 复用分享清理语义，作废凭证并清除冻结正文、专属封面及相应数据页/WAL；逐一检查线上已装版本的 SQLite、独占附件、原稿服务副本和分享素材，移除仍含目标的旧发布目录，再读回确认。共享图片在保留卡名下继续可读，旧书签、块、搜索、图谱、预览和封面均应拒绝或不含目标。旧栈交割时将完整旧根转存为单独标记、脱离服务宿主与部署挂载的离线冷备。切换后若仍在线保留旧根，则沿用原生清理器核对 workspace/data、workspace/history、workspace/repo 快照、operations 回执及原分享库，并从磁盘读回。只给纯程序分包保留版本重叠期。用同一决定记录各清理项，中断后继续核对，全部通过才开闸。Git 历史和离线冷备按现行契约保留。
4. **按应用版本选择回退。** 优先用上一个兼容的 SQLite 程序，配当前核准的内容、归档集合、删除记录及最新认证库。旧思源程序必须配完整旧栈、私有根、维护控制库及可验证的权威账本；若切换后有新内容、归档、撤销或删除，须能向旧栈重放并读回这些变化才可切回。首次迁移没有兼容版本且重放失败时，保持关闸修复。若使用旧冷备的认证库，按既有流程撤销全部会话与分享。演练用“已归档 A、已彻底删除 B、继续可读 C”三个对象，覆盖 A 的原分享、B 的冻结正文/封面和 B/C 的共用图片，同时读取实际磁盘及 HTTP 结果。[旧系统切换与恢复规程](../../docs/agent-environment/commands.md#站主卡片维护与冷备门禁)

## 五、怎样验收速度与完整性

| 指标 | 目标与测法 |

| 首屏 / 再访 | 以已登录 `/cards` 的 20 条结果为主样本，真实浏览器启用 HTTP 缓存、关闭请求拦截。统计至结果可见为止所有响应体的实际编码字节，含 HTML、初始数据、JS、CSS 和首屏图片。冷缓存目标 **< 80,000 字节**；同一会话同版本新开标签页再次输入该地址，含鉴权 HTML 回源，目标 **< 5,000 字节**。另报网络传输总量、SPA 返回导航、强制刷新及重图详情，保留请求瀑布与首屏可读耗时。 |
