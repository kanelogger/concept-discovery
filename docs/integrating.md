# 外部服务、配置与数据集成

当变更接触外部 API、SDK、进程、插件、第三方配置、下载源或用户数据迁移时阅读。具体技术栈与供应商由目标项目决定，本文件只定义核对方式。

## 确认契约和真实执行方

先定位实际处理请求、读写配置和维护状态的组件及版本。存在插件、代理、旧实现或迁移状态时，确认当前运行的是哪一条路径，再决定修改位置。

从对方文档、源码或真实样本确认字段类型、单位、时间格式、路径编码、错误含义和版本边界。区分账户权限、资源不可用、请求格式、内容拒绝、额度和暂时故障，避免一个错误导致整组账户被禁用或无意义重试。

协议看似兼容但结果不同，比较方法、URL、必要请求头、认证范围、正文、重定向和响应。对比材料先脱敏；服务差异限定在对应服务和版本，并验证相邻实现没有被连带改变。

## 权限、凭据与网络

- 明确调用的信任边界、认证身份与最小所需权限。主请求、辅助请求、后台任务和故障回退遵守相同访问限制。
- 真实凭据仅按当前授权在必要位置使用，通过测试专用账户或隔离环境缩小影响；日志、夹具和交付文档不保存明文秘密。
- 新下载源、依赖或校验值核对发布方、可写权限和分发链路。文件与校验值来自同一个不可信来源不能构成独立来源证明。
- 外部请求设置超时、取消和有界重试，区分可重试与永久失败；可能重复产生副作用的操作先定义幂等语义。

## 配置写入与同步

列出配置来源、优先级、所有读者和写者，标明本功能拥有的字段。读取失败保持未知与可恢复的旧值，不能按空配置覆盖。

按“读取 → 用户编辑 → 同步 → 再读取”验证用户修改不会丢失。更新前检查并发变更，按文件格式和平台能力使用原子替换、版本检查或合并。删除凭据或配置项前检查共享标识和其他引用者。

移除集成时明确哪些配置可恢复、哪些用户数据保留，以及旧版本重新运行的行为。

## 数据迁移与恢复

迁移前记录源格式、目标格式、适用用户、识别条件和副作用。对重要数据准备备份并验证可读；不可逆变更明确恢复或补偿边界。

至少验证新建数据、旧数据、已迁移数据、用户自定义值、半完成状态和重复执行。涉及路径迁移时核对符号链接、平台路径及文件内部编码；按实际所有权移动记录，不能仅凭目录名推断归属。

失败保留源数据和进度，重启后不会重复删除、重复计费或跳过未完成项。通过备份恢复或补偿演练确认恢复流程能执行，而非仅确认备份文件存在。

## 验证与交付

先用真实样本构建受控测试，再按授权和风险执行隔离的真实集成检查。存在多个实现、平台或供应商时列出验证矩阵；未覆盖部分保留为未知。

交付说明触发条件、执行方、修改前后行为、配置或数据兼容、失败恢复和实际验证版本。依赖新发布包或外部产物时先确认目标版本确实可获取，再声明依赖已满足。

保留受控环境的命令、输入、实际结果及未覆盖的真实服务或数据范围。
