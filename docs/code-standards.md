# 工程标准

这些规则用于实施和审阅。按变更实际涉及的范围逐项核对，选择项目现行的测试与交付流程。语言风格、框架约束和具体命令以项目实际配置与已确认约定为准。

## 范围与完整路径

| 规则 | 审阅者核对什么 |
| --- | --- |
| 一次变更围绕一个目标。 | 每项行为变化都服务于任务；独立问题拆分，必要的关联修改说明原因。 |
| 修复原报告中的实际问题。 | 使用报告者的输入、入口、环境和操作方式，验收用户的最终目标。 |
| 修复覆盖同类路径。 | 搜索相同条件、其他入口、调用方与邻近分支，说明哪些变化、哪些保持原有行为。 |
| 变更重新推导依赖它的行为。 | 修改公式、字段、枚举、默认值、布局或执行顺序后，核对派生值、缓存、持久数据和相关断言。 |
| 验收贯穿完整操作。 | 从输入到输出跟踪读取、写入、刷新与副作用；按钮成功、单个函数正确不等于用户目标完成。 |
| 尊重已确认的产品决策。 | 先查当前需求与决策记录；确需改变时明确影响，并按用户已有授权推进。 |

发现同类问题但不能在本次修复时，留下具体位置、影响、原因和跟进记录；不能只写“其他地方也可能有”。同一问题的多个验收项全部解决后才能声明完成。

优先复用已有结构和工具；新增抽象、依赖或流程应解决当前需求中的具体问题。可由普通代码或工具可靠完成的解析、校验和转换优先采用确定性实现，按实际需求使用模型处理语义判断。

保持代码库干净。优先修正导致问题的原有逻辑，清理本次变更遗留的临时补丁、死代码与失效说明。遇到容易误用的 API，可在公共边界收窄参数、暴露能力或状态组合，用类型、静态检查或回归测试防止误用。注释用于交代约束、取舍与兼容原因，移除仅复述代码或已经过期的注释。

重复出现且可机械判断的问题，优先接入项目实际执行的类型检查、lint、测试、构建或 CI 入口；以受控反例确认能拦住错误，再恢复正常输入验证通过。依赖语义判断的取舍交由执行者结合测试、工具输出和新增证据核对。

## 数据、配置与失败行为

| 规则 | 审阅者核对什么 |
| --- | --- |
| 区分未知、空值、缺失和失败。 | 读取、解析或校验失败保留错误与可恢复的旧值；权限信息不可读时拒绝受保护操作。 |
| 用户显式设置优先于默认值。 | 核对所有配置来源与优先级；缺失、空值、零值、显式关闭分别验证。 |
| 写入只修改本功能拥有的数据。 | 保留无关字段和用户编辑；覆盖前检查目标版本、格式及备份，损坏数据先保留再处理。 |
| 迁移同时考虑旧数据和新数据。 | 定义识别、重复执行、部分失败、恢复与回滚或补偿方式；说明旧用户何时生效。 |
| 读取外部共享文件考虑写入中间态。 | 半写入、并发更新或短暂不可读不会被解释成删除全部数据；重试有界且可取消。 |
| 写入身份保持一致。 | 保存与读取使用相同标识；删除或覆盖前查清别名、共享凭据与引用者。 |
| 缓存键覆盖复用所需语义。 | 会影响结果的输入、作用域、版本和精度进入键或在命中后复核。 |

预览、计划和 dry run 保持被预览对象及外部状态不变；需要生成报告或临时文件时明确其位置和用途。CLI 参数经过明确解析，未知选项或无效值不能落入待写入数据。

## 权限与外部边界

| 规则 | 审阅者核对什么 |
| --- | --- |
| 限制覆盖所有可达入口。 | 常规请求、辅助调用、批量操作、后台任务和重试路径使用同一权限语义。 |
| 授权判断针对语义而非字符串外观。 | 精确值、通配符、模式和分组之间证明授权集合包含关系；不能证明时拒绝扩权。 |
| 隐私例外按协议位置和来源定义。 | 不因字段名像签名、标识或令牌就跳过用户数据保护；测试嵌套对象和工具参数。 |
| 本机访问仍有信任边界。 | 存在浏览器可达的本地接口时核对 Host、Origin、认证和代理路径；特殊来源与 DNS 重绑定不能绕过保护。 |
| 对外发送数据有明确范围。 | 遥测和诊断日志按字段白名单采集并脱敏；业务上传按用户授权、协议与用途限定内容和目标。发送内容变化同步更新告知、配置与验证。 |
| 第三方契约来自其权威来源。 | 从文档、源码或真实样本确认字段类型、单位和行为，限定服务商差异。 |

文档中发现的安全缺口转成具体修复或跟进事项。记录风险本身不能代替处置。

## 并发、资源与性能

- 阻塞 I/O、回调、等待或消息发送不能持有接收方需要的锁。先确定共享状态与交接顺序；浅复制含可变引用的对象不代表隔离。
- 共享可变状态的读写采用一致的同步方式；账户、租户或功能专属状态按相应身份隔离。新并发路径使用技术栈提供的竞争检查或等效验证。
- 后台任务、计时器、流、子进程和连接有明确拥有者、取消机制及清理路径。请求结束后仍被持有的上下文和回调也要检查。
- 热路径上的新工作按调用频率和最大合理输入评估，关注整包读取、重复解析、内存保留和无界队列。
- 已有体积或性能预算先通过结构调整满足。调整预算时给出测量、增长原因和取舍，按项目既有决策权限处理；不能仅把阈值改到刚好通过。
- 路径比较使用一致的规范化和符号链接语义；涉及安全边界时同时处理路径穿越与检查后被替换的风险。

## 界面与跨环境行为

适用于存在界面或多个运行环境的项目，具体支持范围由项目声明。

- 验收实际用户入口，并检查加载、空数据、错误、取消、重复操作和保存后重读。
- 共用组件、样式、断点或接口变化时核对受影响页面；验证键盘操作、焦点、滚动及目标尺寸，而非照搬参考项目的视觉偏好。
- 多语言项目检查所有支持语言的文案键、占位符和布局；文本长度与输入法组合输入属于真实边界。
- 平台、架构、文件编码、路径格式和时区差异按支持矩阵验证。交叉编译、模拟器或浏览器自动化不能替代未覆盖的真实运行环境。

## 文档与证据

职责、接口、状态、兼容或失败行为改变时，同步更新项目已有的所属实现说明。内部重构保持契约时，在交付记录中说明核对结果即可。

验证绑定实际待交付输入，列明命令或手工步骤、环境、结果与未覆盖项。失败、取消、跳过、零测试和未运行分别记录，均不能记为通过。缺陷验证按风险选择自动回归或手工对照，记录旧实现的反证，无法取得时说明替代证据及缺口。

提交、合并或发布按项目采用的交付流程核对输入与产物。本文件规定审阅要求，不证明仓库已有相应自动检查。
