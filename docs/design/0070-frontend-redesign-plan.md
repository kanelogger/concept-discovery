# 0070 前端交互与品质改造计划

状态：**已按方案实施，待最终设备和用户验收**。2026-10-04 用户选择「案卷 Atlas」视觉方向；改造与验证证据见[任务 0070](../../tasks/0070-frontend-experience-quality.md)。没有修改概念正文、出处或数据库结构。

## 判断与依据

当前产品具有可用的知识库、详情、编辑、Dashboard、模型设置与双语路径。0051 对 Chromium 桌面和 390px 窄屏做过功能验收，[记录](../../tasks/0051-web-acceptance.md)显示当时的 CRUD、返回、修订冲突等关键路径可工作。这些是功能基础，不证明当前已经达到评奖品质。

本轮使用隔离数据库复看了实际页面：

Webby 官方网站评审同时考察[内容、结构与导航、视觉、功能、交互、创新和整体体验](https://www.webbyawards.com/judging-criteria/)。本计划以这些维度作检查框架；最终验收仍由实际产品行为、测试证据和用户体验决定。Awwwards/FWA 的获奖结果不作为可保证的完成条件。

## 目标体验与保留约束

导航改为 **发现 / 知识库 / 工作台 / 模型设置**。打开产品默认进入发现：用户描述情境，立即看到同语言关键词结果；有已选模型且由用户明确提交时，在同页渐进加入最多三条 AI 推荐。两个来源的身份、原因与失败状态始终分明。Dashboard 改名呈现为工作台，但现有指标与数据含义保持不变。

结果列表优先呈现定义、为什么相关、适用边界与出处入口。模型推荐中的 `reason` 明确归属 AI，不能代替 Registry 的来源事实，也不把 `confidence` 数值当作已校准的正确率。关系作为结果之后的第二层探索，不建设占据主流程的全屏图谱。详情仍保留完整文章和结构化字段，缺文章时真实说明降级状态。

编辑器按「核心定义 → 适用情境与边界 → 证据与来源 → 关系/分类」分区；中英切换和分区切换保留未保存内容。保存资格继续由服务端 preview 决定，视觉进度仅表示字段填写状态，不暗示内容已审核。原生确认逐步换为可键盘操作的明确确认界面。

保持本地单用户、现有 SQLite Registry、双语不跨语言回退、来源与修订可追溯、关联类型与方向、模型凭据只在服务端、归档和删除保护。概念正文及出处本次不改写。旧 `src/prototype/` 不纳入实际产品改造。

## 实施顺序

| 切片 | 具体改动 | 完成时的可观察证据 |
| --- | --- | --- |
| 1. 契约与导航 | 先更新需求/产品设计文档；给导航状态加入 `discover` 默认节，并规定旧 URL、深链接、返回与列表滚动恢复。把发现请求状态与编辑状态从庞大的 `App.tsx` 展示代码中分开。 | 旧 `?section=manage` 仍可进知识库；新首页、详情直达、返回、刷新和语言切换不丢查询与来源位置。 |
| 2. 案卷设计系统 | 将根 `DESIGN.md` 的色彩、中文/英文字体、排版、网格、按钮、表单、状态和动效映射到 CSS token 与 Tailwind 语义类；先完成 App shell 和可复用结果/状态组件。 | 桌面与手机第一屏、导航、焦点及对比度截图；组件没有混用旧绿色和新蓝/朱红角色。 |
| 3. 发现与结果合流 | 拆除自动遮挡的推荐抽屉，建立情境输入、关键词结果、AI 加载/空/失败/重试与来源分区。提交时取消旧请求；新查询和切语言不展示过时推荐。直接打开含 `q` 的 URL 先显示关键词，AI 由明确操作请求，避免刷新自动发送内容到远端模型。 | 连接/未连接/超时/空推荐/快速连续查询均能留在同页使用；关键词结果不因模型失败消失。 |
| 4. 可信结果与阅读 | 重排卡片和详情；缺图不占大面积空白。关键词卡从已有 Concept 字段取得边界/来源；AI 最多三条候选通过现有 Concept 详情 API 补齐同语言边界与来源，再与模型理由合成展示。仅当测得额外读取成本明显时才评估窄范围 `/api/discover` 展示字段扩展。 | 两种结果均可看到“原因/边界/来源”，点击概念或关系、直接链接与返回正确；草稿、缺正文、无图与另一语言不可浏览状态不被掩盖。 |
| 5. 维护工作区 | 重新排布知识库过滤、卡/表、分页；编辑器改分区结构并替换放弃/资格降级/归档确认。Dashboard 和模型设置接入同一视觉系统，保留 OAuth 交互与凭据隐私文案。 | 创建、编辑、图片、关系、冲突重载、归档恢复、删除保护、模型选择与授权状态的浏览器路径通过；手机基本编辑可完成。 |
| 6. 品质循环 | 按[品质门槛](0070-quality-gates.md)执行自动测试、浏览器、无障碍、性能、响应式、浏览器矩阵和逐屏视觉自查；每轮记录缺陷→修复→复测。 | `npm run check`、`npm run demo:build` 与任务约定的浏览器证据通过；无重大未决缺陷后交用户实际体验验收。 |

切片按依赖推进。每片只动相关代码和测试，避免一次性重写全部组件后无法定位回归。规范与原型已选定 A，因此不再做新一轮风格选择。

## 验证方法与停止条件

开发全程只使用新建的隔离样本库与临时库验证写操作，不改正式 Registry。行为变化必须有外部可观察结果的回归测试；至少覆盖导航、搜索合流的竞态/失败、双语、编辑脏状态和版本冲突。浏览器逐项记录桌面 1440/1280、平板 768、手机 390/320 的正常与异常状态。最终按 WCAG 2.2 AA、性能、Chrome/Firefox/Safari、iOS Safari/Android Chrome 和用户体验验收执行；缺少实际设备或浏览器时明确记为未通过对应门槛，不用 Chromium 模拟冒充。

评奖品质的主观部分靠逐屏审查和用户最终体验验收，不靠自评分数或单次 Lighthouse 分数。若功能、安全、可访问性、性能或兼容性存在高影响缺陷，则继续改并重测。当前产品的 12 样本人工内容签收、30 天使用与推荐质量 Gate 仍是独立事项；它们不会因为界面改造被记录为已完成。
