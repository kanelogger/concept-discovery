# ADR 0001：先建立可验证的协作底座

- 日期：2026-09-23
- 状态：已采用，范围限于开发环境；产品技术栈仍待确定
- 来源：用户指定的《把仓库变成 Agent 的工作环境》及 [PRD](../method-system-prd-v0.1.md)、[清洗稿](../method-registry-curated-v0.1.md)

## 背景

初始化前只有 README、LICENSE 和两份未纳入版本控制的产品材料，没有应用、服务、包配置或测试。目标是让后续人与 Agent 仅凭仓库恢复事实、执行正确流程并验证结果。

参考材料提出角色、规则、事实、过程、状态和长期经验分层，并要求按项目裁剪。它的部分示例引用了其他项目的 harness、Stage Result 和脚本；本仓库没有这些能力，不复制那些命令或审批流程。

## 决策

1. 根 `AGENTS.md` 只做稳定入口，具体规则、环境、产品契约和任务记录分开存放。
2. 使用 Node 24 内置 API 编写环境检查和测试，零第三方依赖；本机已有该运行时，未来 Web 工具也易于接入。此选择不预先决定应用框架、存储或模型供应商。
3. 用 `project.json` 代替参考模板的 YAML 清单，以内置 JSON 解析校验；命令实现只定义在 package.json，清单保存脚本引用。
4. 状态文件记录任务阶段、阻塞、证据和下一步，配套人工维护说明及确定性校验；不实现工作流引擎或把它当成授权机制。
5. 只创建真实会使用的资源。当前不添加空的 Skill、Hook、MCP、服务、凭据或发布配置。后续有可复用语义流程时再增加项目 Skill。
6. 原始产品材料保持不变；未统一字段、准入标准和来源的问题记入契约及待办，不自动导入正式 Registry。

## 代价与复核

协作工具要求安装 Node；即便未来应用采用其他运行时，这一小型工具仍需维护，届时可据实际成本替换。状态和语义真实性仍靠执行者及审阅者，静态检查只防止可检测的结构漂移。

环境检查通过只能证明协作底座可运行。产品业务功能、浏览器体验、语义推荐质量和远端 CI 都需要各自真实验证。

首次引入应用框架、存储、项目 Skill 或工作流自动化时复核本决策；替代决定应以新 ADR 链接本记录。
