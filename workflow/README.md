# 任务流程与交接

目标：从仓库入口能知道当前任务、实际结果和下一步，避免同一信息重复维护。

## 开始与执行

1. 读取根 `AGENTS.md`、[状态文件](../workflow-state.json)，检查工作树；有任务时读取 `task_file`，核对当前事实。
2. 新的实现任务在 `tasks/` 创建独立编号文件，参考[任务模板](task-template.md)。记录目标、范围、关键取舍和验收条件；只读导读不必写文件。
3. `workflow-state.json` 只保留当前任务指针、阶段、日期、摘要和必要下一步。详细验证结果只写任务文件，不重复填写命令流水。
4. 实现期间保留已有和并发修改，必要时明确文件所有权。常规可逆工作持续完成；方向性歧义无法从上下文解决时询问用户。
5. 按[验证规则](../rules/testing.md)选择检查，记录实际结果与未覆盖范围。失败先修复；不因跨模块或阶段交付自动扩大到全量验收。
6. 完成审查、清理和交接后，将阶段设为 `complete`，按 Git 规则提交任务相关改动。新任务切换指针，保留旧记录。

## 状态约定

`workflow-state.json` 是交接入口，不是权限系统、锁或调度器。基础字段为 `schema_version`、`task_id`、`task_file`、`phase`、`updated_at` 和 `summary`，可按需附 `next_actions` 或 `blockers`。

| phase | 含义 |
| --- | --- |
| `idle` | 无当前任务，任务指针为 `null` |
| `planning` | 明确目标、范围和验收 |
| `implementation` | 实现已授权工作 |
| `verification` | 验证、审查和清理 |
| `blocked` | 在任务中说明阻塞原因和解除条件 |
| `complete` | 当前范围完成，任务中有实际结果和遗留事项 |

`task_file` 使用 `tasks/<task_id>.md`；日期使用有效 ISO 日期或带时区的时间。`npm run validate`检查入口路径、命令引用和基础状态结构，不证明功能正确或命令实际运行。旧的 `required_checks` / `verification` 字段兼容保留，不再作为完成门禁。

## 事实与长期记录

- 产品边界放 `specs/`，实现事实直接引用源码、配置和测试。
- 本轮进度、验证、失败和取舍放任务文件；跨任务决定才进入长期文档。
- 原始材料注明状态，不把草稿或历史记录当作当前能力。
- 结束时只清理本轮有归属记录的临时资源，保护正式资料；失败和残留写明恢复方法。

从 `AGENTS.md` 出发应能回答：当前产品状态、任务是否完成、如何运行检查、尚未决定什么，以及下一步是什么。
