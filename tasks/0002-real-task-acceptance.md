Status: ready-for-human

## 目标与范围

用户要求选 10–20 个真实任务，验收“找对卡 → 正确应用 → 表达清楚”。从现有项目的实际工作记录重构 15 个提问，明确来源和测试改写；不把改写称为用户原话。通过正式应用只读 CLI 验收，不修改知识、模型配置或其他项目。

原始卡片、场景、模型响应和逐项评分保存在 Git 忽略的 `.local/task-fit-20261106/`。任务文档仅记录脱敏方法和结论。先冻结案例及判断标准，再运行 ask；若模型不可用，独立评估 Agent 的 search/get 链路，并如实区分覆盖范围。

## 问题及建议顺序

1. **P1：从业务描述找到概念不稳定。** 02、05、08无匹配；直接概念名检索确认部分相关卡存在。增加任务性质与机制层面的检索线索，检查候选排序及片段选择，用失败案例回归。当前没有生成查询词或候选清单日志，不能精确归因于某一个检索阶段。
2. **P1：模型输出异常让整次任务中断。** 06、09、11统一报 ask_invalid_output；保留脱敏阶段、finish_reason及字段校验信息后，判断是否需要缩短输出、调整预算或一次有界修复。现有证据无法区分截断、JSON、字段或引用校验等原因；维持无效引用拒绝。
3. **P2：方法建议与技术资料缺口未区分。** 03、10应能说明一般方法并列待补技术细节；15应继续拒绝编造具体配置。此为对方法型需求的产品判断，不宣称库内存在专门技术指南。
4. **P2：边界归属和最终交付需要核对。** 07的“只适用于可逆、低风险试用”不在循证实践原文中；12缺完整备份范围；04没有完成两句使用者文案。把卡片边界、任务条件及应用推导区分开，优先呈现请求的产物。
5. **P2：减少重复引文和弱相关卡。** 01的重复示例来自正文与字段重复。优先在证据提取层去重，未授权重写知识内容。
