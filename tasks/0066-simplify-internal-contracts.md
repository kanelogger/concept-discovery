Status: ready-for-agent

## 目标与范围

按用户要求检查项目代码的维护负担，在现有[产品契约](../specs/product-contract.md)内实施可验证的简化。基线为 `cd2fe3f`，工作树已有一项原稿删除，排除在本任务之外。上轮 [0065](0065-simplify-codebase.md) 的删除已存在于基线。

## 调查与决策

并行调查网页、服务端、原稿与后台维护，主执行者另查 npm 入口、构建、部署、CI 和测试。按消费者证据和退役的维护义务选择改动。

拟实施两项。分别完成残留检查与定向回归，再运行完整检查。

1. `diffBlocks` 复用已计算的 Markdown 语义键。准备旧块 ID 到旧数组位置的映射，继续按相同的 ID 识别更新、移位和插入。通过原位置读取旧键，避免在组装更新操作时重复解析。保留用于其他调用方的 `markdownEquivalent`，以及原有 LCS 配对、同块内容等价规则、写入保护和持久回执。使用现有差分回归与旧版计划对照检查。另以隔离思源核对原稿写入、写后读回、恢复和拒绝。如果重现 0065 中测试错误目标缺少配置的问题，仅在隔离测试副本补齐合成夹具，并核对挂载拒绝仍实际发生。
2. 把图谱和场景图鉴对 `学科：` 标签的解释归到现有标签模块。保持原始标签顺序、全半角冒号、空名称处理和同名合并。图谱无有效学科时回退到完整的去重标签数组，包含原始空学科标记。图鉴继续遵守作者编写的学科目录。原稿导出与站主新增中的学科验证各有用途，保持独立。通过图谱、图鉴和列表回归检查。

### 已选项的证明

- **文档差分。** `lib/documents.mjs` 自早期实现即同时使用新旧语义键配对、对同一对正文再解析判断更新。保存流程将差分步骤冻结到回执，原稿同步和数据库优先编辑可进入。按旧 ID 查回原数组位置，保留映射覆盖行为、旧块 ID、移位顺序、插入锚点和原块属性。创建及保存读回照常调用同一个 Markdown 等价函数。退役一次重复的等价计算路径，风险集中在保存计划，用逐项对照和隔离内核读回验证。
- **学科名称。** 场景图鉴 `dfa8ccc` 与图谱 `925188f` 分别引入同一标签规则。两个消费者都读取 `tagsFromNodes` 的正文标签。既有实现的两个正则在筛掉空名后语义一致。集中解析与去重，保留各路 Markdown 预处理及其调用方自己的回退和目录筛选。退役两处局部规则，用一个共享定义接替，无配置或数据迁移。

独立方案审阅要求补真实内核验证，并明确空学科标签回退边界。采纳后给现有图谱回归增加同名去重及空学科回退输入，并用旧实现先验证相同输出。
