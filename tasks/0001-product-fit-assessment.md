## 评估结论

方向符合，核心使用链路已有实现；学习记忆、表达改善的实际效果，以及长期远端运行尚未证实。适合作为个人知识服务持续试用，不能据现有测试宣布全部用户目标达成。

| 用户目标 | 判断 | 当前依据与边界 |
| --- | --- | --- |
| 自己持续整理知识卡 | 基本符合 | [网页编辑](../web/app.jsx)只要求标题，正文自由整理理解、来源、例子和边界；[整篇写入](../lib/documents.mjs)有版本冲突、备份和恢复。早期固定字段卡、复杂布局仍需 Agent 块维护，有整理摩擦。 |
| 帮助理解与记住 | 理解有支持；记忆支持偏弱 | 正文、来源、例子、自测文字可承载学习；[契约](../specs/product-contract.md)明确排除复习、答案揭示、评分和排程。可以人工回忆、自测，但没有形成产品内的记忆检验流程，也没有长期学习效果证据。排除复杂复习系统不必然违背需求。 |
| 具体任务找到适用概念和方法 | 功能已实现，效果待测 | [ask](../lib/ask.mjs)提取 1–4 条查询，输出至多 5 张卡、理由、边界、步骤与缺口。[检索](../lib/ask-evidence.mjs)每条查询取至多 20 个匹配，最终取 8 个候选，每卡至多 3 段、2000 字符；[底层匹配](../lib/library-scope.mjs)仍为关键词 LIKE。任务词与卡片措辞不一致、相关卡未入候选或关键边界未入片段时，可能漏检或推导不足。 |
| 帮助思考 | 基本符合 | 应用建议包含步骤、理由、边界与真实引文，可作为思考输入；程序核对引用身份和归属，不证明建议在语义上正确或适用。 |
| 更准确、简洁地向 AI 或别人表达 | 部分符合 | 卡片及应用建议提供概念与材料；[Agent Skill](../skills/concept-discovery/SKILL.md)把组织表达交给调用方 Agent。ask 固定输出没有面向具体读者的表达稿/任务说明，也没有表达效果评估。可通过明确要求外部 Agent 完成，无须立即新增网页写作功能。 |
| 个人长期在线知识服务 | 架构符合；运行目标未完成验证 | [Compose](../deploy/compose.yaml)有持久卷、自动重启、内部内核与单一应用入口。本轮确认正式应用在 127.0.0.1:6806 响应，容器运行；未证明远端 HTTPS、机器离线时可用、异地备份和完整灾备恢复。仓库提供[人工托管与备份说明](../docs/reading-experience.md)，操作级恢复不等同于整库灾备。 |
| 网页学习查找，Agent 显式查询、应用、维护 | 符合设计与实现分工 | [命令入口](../lib/commands.mjs)与[客户端](../lib/client.mjs)共享知识源，网页会话与 Agent Token 分离。Skill 约束显式触发；网页 ask 由提交动作触发且只读。用户主动网页提问符合这一方向；显式授权仍依赖调用方 Agent 遵守规则。 |

优先建议：先用 10–20 个真实任务做小规模质量验收，事先标注预期卡片，检查是否找对、边界是否正确、建议是否可执行、最终表达能否直接使用；根据漏检原因再决定是否调整检索。在卡片中试行少量“何时使用、自己的例子、自测问题”，隔几天用自己的话解释并记录困难。随后完成常驻 HTTPS 服务、异地完整备份及恢复到新目录的演练。无需先增加 MCP、知识图谱、复杂复习排程等范围。
