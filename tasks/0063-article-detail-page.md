# 0063：文章式 Concept 详情页

Status: complete

## 目标与范围

用户选择[方案 B](0062-article-detail-options.md)：点击卡片进入完整阅读页，每种语言可维护独立文章正文。沿用同一个 Concept 的 ID、关系、出处、双语、修订和维护机制。更新[需求文档](../docs/需求文档.md)与[产品设计文档](../docs/产品设计文档.md)；不新增 Article 实体。

## 验收条件

- 点击卡片进入文章阅读页；直接 URL、刷新、关系跳转、浏览器返回和返回列表均有效，列表条件与滚动位置保留。
- 中英文正文独立编辑和显示；旧条目缺少正文仍能阅读已有结构化内容，并提示文章待补，不将自动拼接内容存成文章。
- 文章修改通过现有版本检查与修订记录持久化；非法类型拒绝且旧 JSON 可读。
- 卡片、检索、推荐继续使用现有结构化字段；文章正文不自动同步到这些字段。
- 完成隔离数据的服务测试、构建与浏览器关键路径验证，执行 `npm run check`。

## 工作分工与进度

当前 Agent 独立负责产品文档、Registry、Web 编辑和阅读页及回归验证。工作树开始时干净；分支 `codex/article-detail-page`。

已在现有 Concept 的语言数据中新增 `article_body`；原编辑器可修改 Markdown 正文，阅读页按文章排版。导入脚本用目录 slug 精确对应 ID，先预检全部目标；图片导入现有媒体表。当前库原有 6 张卡片保持不变，其中 `first-principles`、`hard-choice-model`、`minto-pyramid`、`ooda-loop` 的英文正文已从对应私有文件导入，中文正文保持空白。导入前的本机快照为 `.local/backups/articles-before-import-2026-09-29T02-50-17-432Z.sqlite`；原始资料未改动。

## 决策与未决事项

- 用户补充指定 `docs/private-project/models-data/` 为文章来源。原始资料为 25 篇英文 Markdown，包含标题、列表、表格及本地 PNG；正文改为可编辑 Markdown，阅读页不执行 HTML，图片只接受导入后的本地资产地址。原始私有资料保持不变，不进入提交。
- 采用扩展现有每语言 Concept 字段，不建文章表。当前文章与 Concept 为一对一，沿用 ID、版本冲突与修订；目录名直接对应 `Concept.id`。4 篇已有卡片已导入；其余 21 篇若导入会新增卡片，用户尚未指定扩大范围，因此本轮未创建。
- 旧条目读取时补空正文，仅用于兼容；不会修改旧记录与修订。阅读页以正文为主，正文为空时显示现有结构化章节并提示待补。
- 来源、关系沿用原字段和管理操作。正文可能与结构化字段表达同一知识，维护者负责一致性；界面明确字段用途。
- 文章编辑器支持修改 Markdown 文本及已有图片引用；目前没有正文新增图片的上传控件。来源文件重新导入时若正文已被编辑，脚本拒绝覆盖。
