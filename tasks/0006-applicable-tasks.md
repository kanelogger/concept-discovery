Status: ready-for-human

## 目标与范围

复用当前 Markdown 的「适用情境」章节作为适用任务；新卡缺少章节时保存可选「适用任务」章节。现有 summary 为正文摘录，不能作为独立任务简介。卡名和描述参与候选检索，回答仍用正文证据。编辑页提供描述及建议采用/修改/丢弃，保存前不写入。

用户授权少量真实卡试做及复用已配置模型；选合成谬误、知识诅咒、影响—投入矩阵三张，其他真实内容不改。凭据仅在现有服务端使用。

## 完成结果（2026-11-07）

- 复用适用情境 Markdown 章节；编辑时将该章节映射到独立描述框，保存合回同一文档。章节缺失且描述为空时不新增，保留粘贴内容和其他章节；同名标题定位使用 AST，避开代码示例。没有新增数据库字段或批量迁移。
- 找卡目录携带卡名和描述，最多200条/12000字符；描述只用于检索，完整原描述用于排除回答证据，目录截断也不能将描述当成证据。找不到目录条目的候选也读取原章节过滤。
- 新增只读 polish-description 命令，共用鉴权、现有模型、90秒期限、有限重生成、取消与单请求限制。外发仅标题和当前描述；采用/修改/丢弃保留本地草稿，只有保存写入。
- 保留旧写协议。真实试点发现列表转段落后旧子块索引未刷新会导致保存待核对，增加 updateBlock 后 flush 再核对存活子块。首张卡用同一回执核对成功；随后两张正常保存成功。

### 试点

| 卡片 | 写入的适用任务 |
| --- | --- |
| 合成谬误 | 当你根据各个成员或组件的表现推断整体表现时，用它检查这种推断是否成立。它帮助你找出需要核实的聚合假设、相互作用和反例。 |
| 知识诅咒 | 向新手解释专业内容，或编写教学材料、操作文档和产品说明时使用。它帮助你找出读者缺少的前提，补足术语和步骤，并通过试读检查说明是否易懂。 |
| 影响—投入矩阵 | 当你面对较长的任务清单、不确定先做哪项，或需要比较多个项目的潜在收益与投入、讨论团队资源分配和优先级时，可以用这张卡梳理影响与投入的对应关系，辅助判断先做什么。 |

前三张均用真实浏览器生成建议及点保存；前两张在建议框调整表述，第三张直接采用。浏览器验证丢弃保留原描述、采用后尚未保存、重开编辑页显示持久化描述且保存禁用；失败保留/迟到结果丢弃有自动回归。CLI 独立读回确认除描述章节外 Markdown 语义相同；另58张的ID/标题/更新时间清单不变，总数61。

三个实际问题分别描述组件与整体判断、新手操作说明、有限时间优先级，全部 answered，首卡分别命中上述三张；耗时6.3/10.1/5.5秒。引用来自正文，未引用新描述。这是三次可用性试用，没有旧版对照，不证明推荐质量全面提升。
