# 知识卡树形浏览评估

Status: ready-for-human

## 目标与范围

评估知识图谱作为新的浏览方式。类目和场景提供横向入口，纵向三层都表达概念，外围可细化到学科里的具体概念。节点之间由人建立关联。本轮交付产品判断与试验条件。

## 评估

现有[列表](../web/app.jsx)支持关键词、标签、时间筛选与按问题找卡。[文档读取](../lib/documents.mjs)从 Markdown 读取标签，[现有契约](../specs/product-contract.md)将适用任务作为可选描述。已有正文内链，旧结构化关系也能在[旧卡读取逻辑](../lib/knowledge.mjs)中读取。浏览时缺少的是从一个熟悉场景进入、看见一组知识及其不同抽象层次的路径。

[Munger Models 首页](https://mungermodels.com/)的索引按学科列出思维模型，可看成「学科 → 模型」两层。[图谱页](https://mungermodels.com/graph)按学科区分模型节点，模型之间有连线。[安全边际详情](https://mungermodels.com/models/margin-of-safety)说明关联理由，也在正文中叙述案例。

建议将类目、场景用于导航，同一张概念卡可以从多处进入。三层暂用「通用概念 → 核心机制或模型 → 学科内的具体概念」表示相对的抽象程度。例如「风险缓冲 → 安全边际 → 工程安全系数」，桥梁如何预留承载余量可以写在卡片正文中。人建立关系并说明理由，区分「在某学科中的具体体现」与「常一起使用」等不同关系。浏览时可以从任意概念出发，再往上看通用思想或往外看学科概念。

## 决策与未决事项

值得先验证小范围图谱。中间层是否帮助理解抽象概念如何迁移到不同学科，是相较参考站点多做一层的判断依据。三层名称、选取哪些场景和卡片、关联是否需要结构化仍待试验。图谱暂允许局部缺层，不要求全库每张卡都填一个固定层级。

## 交接

可选一个场景、两个相关学科和约 10–15 张已有概念卡，手连小图。对比「学科直接列卡」和「沿三层展开」，观察能否从具体概念反查上位思想、能否借中间层找到另一学科的相关概念、能否用一句话解释每条边。用试验结果决定哪些地方值得展开三层。
