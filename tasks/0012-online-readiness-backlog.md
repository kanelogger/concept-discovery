# 线上部署与项目待办

Status: ready-for-human

## 目标与范围

让个人知识库在本机关闭时仍能访问。首版沿用[产品契约](../specs/product-contract.md)和[现有 Compose](../deploy/compose.yaml)，将应用和内部思源部署到一台常驻主机，通过固定 HTTPS 地址访问。本任务梳理待办与验收条件，实际部署另行执行。

[最近一次本地验收](0011-local-data-access.md)确认 61 张卡可列出并读回一张正文。远端运行、整库灾备和迁移后的读写仍待验证。梳理时 `main` 比 `origin/main` 领先 4 个提交，上线应明确记录实际部署的提交。

## 需要用户决定

1. **主机和地址。** 使用已有常驻主机，或准备一台云主机。提供服务器和域名的管理入口。
2. **访问范围。** 推荐先采用个人私网或接入层访问限制。若需要普通浏览器从任意网络直达，则按公网入口验收。
3. **切换窗口。** 确认一段可以暂停本地编辑的时间。是否首发启用按问题找卡可以单独决定。

## P0 · 上线前准备

- [ ] **定版与准备主机。** 固定发布提交，确认目标主机可构建应用并拉取固定版本镜像，配置 Docker 开机启动、持久盘和服务目录权限。依据[验证规则](../rules/testing.md)，用隔离库完成包含代码的发布验收 `npm run check:full -- --ego-run <id>`。
- [ ] **做完整备份和恢复演练。** 暂停写入，备份正式 `workspace`（含附件）、`operations`（含备份和回执）及恢复所需配置和凭据。保护副本并异地保存，恢复到隔离新目录，核对卡片 ID 清单，抽查正文、附件、内链与补充阅读。基线为最近已核验的 61 张，切换时以最新清单为准。依据[托管与备份说明](../docs/reading-experience.md)。
- [ ] **用样本库跑通线上入口。** 部署双容器并设 HTTPS 反向代理，应用保持回环绑定，内核仅容器内可达；将 `service.json` 的 `publicUrl` 设为实际 HTTPS 源。验证访问控制、登录、请求 Origin、附件上传与长请求超时；生产使用强访问码和独立 Agent Token。配置与凭据单独传输和存放。

## P0 · 正式切换与验收

- [ ] **迁移当前正式库。** 在切换窗口冻结本机写入，取最终一致快照，恢复到服务器的持久目录并核对库身份、内核配置和 UID/GID。保留本机快照作为回退点，切换后由线上实例承接日常写入。若线上已有新写入，回退前先保护这些变更。
- [ ] **在异地网络验收。** 本机服务关闭时，确认远端可登录、搜索和打开原卡及附件，未授权请求无法读库。用测试卡完成编辑、图片上传和重启读回；将 Agent 客户端指向 HTTPS 地址，用独立令牌完成读回。若首发启用模型，再验收一次真实问题及其引用链接。
- [ ] **确认运维可交接。** 配置自动异地备份、可用性和备份失败提醒，实际验证一次主机重启后服务恢复。记录启动、升级、恢复和回退步骤及责任人。
