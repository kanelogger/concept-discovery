# 0013：访谈并完善 Concept Discovery PRD

## 目标与范围

按用户指定的 `grill-with-docs` 工作流，以多轮访谈检验 [PRD](../docs/method-system-prd-v0.1.md) 的关键产品决定；对已确认术语维护 [领域词汇表](../CONTEXT.md)，对真正难以逆转的取舍按需写 ADR。未取得用户对设计树的共同理解前，不据假设改写 PRD。

## 验收条件

- 每轮集中询问当前可以独立决定的问题，给出推荐答案；待用户回答后再推进依赖问题。
- 对现有 PRD 与用户回答之间的冲突给出具体场景并解决；确认的结论同步到 PRD、产品契约、词汇表和相关待办。
- 与用户确认设计树已无未问分支；运行 `npm run validate` 并审查差异。

## 工作分工与进度

- 负责人：主 Agent；当前只维护访谈记录、状态和已确认的领域术语，后续按回答修订 PRD 等文档。
- 进度：两轮建议及最后的类型边界均获用户确认；PRD v0.6、产品契约、待办、文档索引与词汇表已同步并验证。

## 决策与未决事项

- 已定边界：Card First、`cn` / `en` 独立内容与配图、可选 Wiki Link、Relation 与 Recipe 分离、用户选择后 Apply；见 [产品契约](../specs/product-contract.md)。
- 第一轮已确认：Concept 是有名称、可说明出处的专业领域或方法论术语；现阶段只收纯文本，不自动核验出处。`cn` / `en` 各自判断能否推荐；Skill 只在用户主动调用时运行；模型支持本地与可配置远端，首次远端发送上下文前告知并取得选择，默认不上传。
- 第二轮已确认：普通专业词条可收入 Concept 库，只有内容齐备的语言版本参与推荐；出处是各语言必填的纯文本 `source_text`，只检查是否非空；显式命令和明确的自然语言请求都算主动调用；Web 只提供 Concept CRUD 与 Dashboard，不提供 Recommendation Playground 或 Prompt 展示，推荐接口保留开发用评测入口；没有本地模型时先提示配置或选择远端模型，用户选择前不发送上下文、不伪造推荐。
- 最后一个类型冲突已解决：`interaction_type` 与 `epistemic_type` 独立可空，已填写时遵守枚举；普通术语不强制归入方法论分类，卡片/详情未填则不展示类型，推荐资格不依赖类型。
- 本次未新增 ADR：这些产品边界已直接写入 PRD 和产品契约，没有额外的技术锁定或需要解释的非显然取舍。
- 本轮不重问已明确的字段和界面取向；若访谈发现前次推断与用户意图冲突，以用户最新回答修订。
