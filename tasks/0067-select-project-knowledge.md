# 0067：筛选适合项目的候选知识点

Status: ready-for-human

## 目标与范围

从用户指定的 [80 条知识清单](../docs/knowledge-list.json) 选择适合当前 Concept Discovery 知识库优先整理的内容，输出独立 JSON 文件。依据 [需求文档](../docs/需求文档.md) 的广义 Concept 范围、情境检索和内容质量要求，以及 [产品设计文档](../docs/产品设计文档.md) 的字段与关系设计。

## 验收条件

- 新文件保留入选条目的全部原始字段、中英文内容和原有相对顺序，数量与 ID 一致且无重复。
- 筛选说明包含标准、逐条入选理由、具体使用场景及暂缓理由；标注待补出处和适用边界。
- 原清单与个人数据库保持原样；本任务不联网核验来源、不导入数据库，不将候选筛选视为内容签收。
- 执行数据完整性核对、`npm run validate` 和差异审查。

## 工作分工与进度

当前 Agent 独立负责输出文件、本任务记录、任务索引和工作流状态。开始时分支为 `codex/article-detail-page`，工作树干净；前一任务 0066 已完成。筛选文件已完成，内容后续可供维护者审阅。

结果见 [knowledge-list.selected.json](../docs/knowledge-list.selected.json)：40 条入选、40 条暂缓。入选分为证据与判断 14 条、系统与协作 9 条、表达与理解 4 条、决策与行动 13 条。14 条在至少一种语言中存在占位出处，22 条缺少至少一种语言的适用边界；两类数量存在交集。筛选元数据与原始 `items` 分开，避免改变原记录。

## 决策与未决事项

- “适合本项目”按适合作为知识库内容解释，兼顾日常判断、决策、系统与协作；不只筛选用于开发本仓库的技术知识。
- 优先选择能对应具体情境、可转化为诊断问题或行动的条目。未入选表示本轮暂缓，不改变产品的广义收录范围，也不沿用旧 Core / Pack 分类。
- 内容相关性与原稿质量分开记录。原稿中的占位出处、绝对化措辞和术语歧义保留并注明复核事项。
- 未与个人库逐条去重，因此不能把候选数量解释为可新增条数。
