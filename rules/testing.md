# 验证规则

## 按影响范围选择

计划写明影响范围、验收场景、可观察结果、验证方法和证据位置。局部行为先跑相关永久回归，并完成一条从真实入口到最终结果的链路；共享内容读写、协议、版本/回执、鉴权、存储或部署变化扩大到所有受影响调用方及拒绝路径。纯文档修改执行引用、命令一致性与差异检查，注明业务链路不适用。

跨模块交付、包含代码的阶段/发布验收、影响全局的依赖/构建/测试基础设施，或影响范围无法可靠界定时，集中执行一次 `npm run check:full -- --ego-run <id>`。同一聚合入口覆盖的检查无需重复；复用结果须匹配源码、测试、配置、环境和仍可核验的证据。验证后修改实现，重跑受影响检查并重新判断全量范围。失败、跳过、未覆盖或不可用如实记录。

## 证据分层

- `npm test`：关键 Node 与工具回归，验证输入、状态、受保护写入和错误边界。
- `npm run test:integration`：独立真实思源/应用 API、安装后的 CLI、写后读回、恢复、重启及发布资产一致性。
- `npm run test:browser`：显式白名单中的五组 Playwright，覆盖启动竞态、请求乱序、未知结果续跑、版本冲突、上传/401 后草稿保护。仅保留必要正常 setup；日常流程由 ego-lite 验收。
- `npm run test:ego -- start`：建立随机 project/端口的隔离栈。随后遵循已安装版本的 `ego-browser skill`，通过真实可见控件操作；页面 evaluate 仅做只读观察，API/CLI 用于样本准备、明确的 Agent 协作步骤和持久化读回。

Ego 必需检查点：sign-in（登录/空态/退出）、authoring（真实编辑/格式/预览/图片/保存）、navigation（搜索、列表分页、内链/历史及放弃编辑）、compatibility（旧卡/复杂结构只读及来源链接）、agent-roundtrip（Agent 追加、网页编辑、恢复和重启读回）、desktop（1280/1440、键盘、长内容和状态）。搜索最多显示前20条，只有列表分页。

通过 `npm run test:ego -- record --run <id> --checkpoint <name> --input <json>` 记录预期、实际观察、实例/空间、截图、snapshot；写入及兼容性检查还需独立 CLI/API 读回。截图本身不证明持久化。`npm run test:ego -- cleanup --run <id> --browser-finished <json>` 回收本次实例后，`npm run test:ego -- verify --run <id>` 核对输入、证据和清理。完整入口只接受明确 run ID，不挑选“最新报告”，不以自动测试代替 ego。

## 审阅、清理与完成

独立 Agent 首先核对实例/目标ID、预期与原始读回、字段/hash、操作回执、命令结果、版本/环境及范围是否支持结论，再审代码；缺证据记未证实。起止摘要检测输入差异，验收期间停止相关文件的并发编辑。

从首次分配资源起登记归属。成功、失败和中断均执行清理：等待本轮子进程结束，按精确 Compose project 核对容器/卷/网络，移除本轮应用镜像标签和临时目录；清理成功才标记完成。失败保留诊断及恢复配置，允许重试；SIGKILL 等无法执行收尾时从已保存 run 记录恢复。

只回收本轮合成资料、凭据、服务和 Agent 创建的浏览器空间；保护真实库、用户浏览器资料及其他任务资源。截图/读回先保存在样本目录之外供审阅，结束保留少量必要脱敏证据和永久回归，清除一次性产物。当前不包含移动端、旧复习能力、正式部署或远端 CI 验收。

浏览器空间结束回执由真实 `await task.finish({keep:[]})` 成功后保存为 `{spaceId,finishedAt,result:"resolved"}`；通过 cleanup 的 `--browser-finished` 导入。完整门禁核对空间归属、结束时间及回执摘要；未提供回执仍可清理失败候选，但不能通过交付门禁。

结束浏览器空间前运行 `npm run test:ego -- status --run <id> --require-complete`，必须确认恰好六个检查点通过；独立CLI读回与检查点记录由同一run原子更新协议合并，保留原始失败与恢复信息。
