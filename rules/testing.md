# 验证规则

| 改动 | 最小有效验证 |
| --- | --- |
| 文档、任务、状态和入口 | `npm run validate`，人工检查来源及状态是否真实 |
| 环境脚本或共享配置 | `npm run doctor`、`npm run check`；故障路径加自动化回归测试 |
| 未来 Schema / 数据导入 | 合法与非法数据、重复 ID、引用完整性、导入失败不破坏原数据 |
| 未来推荐与 Compose | 0 和 3 条边界、缺少上下文、禁用/排除词条、用户选择及语义质量样例 |
| 未来 Web / 持久化 | 临时数据目录运行实际读写流程及浏览器关键路径 |

后面三类是实现相应功能时的要求，目前尚无这些测试或功能。不要把环境检查通过当作产品验收。

行为变更的测试应检验外部可观察结果或真实故障边界，不只复制实现。测试使用隔离的临时目录，结束时清理；禁止覆盖用户 Registry、对话或日志。

任务记录保留命令、执行日期、退出码、关键结果和未覆盖范围。`passed` 必须有实际执行证据，`skipped` 说明原因；本地通过不等于远端 CI 通过。改动后旧结果失效，按影响范围重跑。
