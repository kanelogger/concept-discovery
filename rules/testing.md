# 验证规则

## 按风险选择

日常入口 `npm run check` 校验仓库入口和任务指针，离线检查原稿格式及引用，再运行 Node 回归。它不启动 Docker、浏览器或外部模型。项目目前使用本地验证。只运行能验证本次改动的检查；跨模块或阶段交付本身不触发全量验收。

| 改动 | 所需验证 |
| --- | --- |
| 文档、文案 | `npm run validate`、`git diff --check`；无需业务链路 |
| 页面样式或交互 | `npm run build:web`、相关状态回归及受影响页面的一次浏览器检查 |
| 纯业务计算、输入校验 | 相关 Node 测试；完成时运行 `npm run check` |
| 读写命令、版本、回执、鉴权 | 相关 Node 回归，加 `npm run test:integration` 的真实内核链路及拒绝路径 |
| 浏览器请求顺序、旧链接、阅读位置或前进后退 | 相关 Node 回归，加 `npm run test:browser` |
| 存储布局、内核升级、备份/恢复协议 | 真实集成及独立冷备恢复检查；按改动补充浏览器检查 |
| 构建、依赖或部署 | 构建及真实集成；界面依赖变化时补充浏览器检查 |

选择依据和实际结果只记在本任务文件一处。相同产物已通过的检查无需重复运行；后续改动只重跑受影响范围。失败、跳过、未覆盖或不可用必须如实写明，不把历史结果当作当前通过。

## 保留有价值的回归

- Node 测试覆盖输入、状态转换、受保护写入及错误边界。测试应验证可观察行为，不镜像实现细节。
- 真实集成使用独立思源和应用，验证公开 HTTP/CLI 的读取与写入拒绝，以及本地原稿写后读回、版本冲突、未知结果及受保护恢复。同源网页和持有有效 Agent 令牌的客户端均须遵守公开只读边界。冷备恢复是独立可选检查，不随每次集成执行。
- Playwright 验证旧编辑链接转到阅读、迟到的搜索或详情响应不会替换当前选择，以及返回卡片、资料、图鉴和图谱时的阅读位置。测试数据用隔离实例的本地维护夹具建立，浏览器通过真实公开接口读取。按改动抽查桌面宽度、键盘、加载、错误与重试。涉及会话失效时，检查知识区关闭且迟到的响应无法重显旧内容。
- 浏览器检查可使用合适的已安装工具，不强制 Ego、固定六检查点、截图哈希或浏览器结束回执。截图用于帮助观察；涉及写入仍须核对持久化结果。

## 隔离与清理

测试只使用合成资料和独立临时库，不读写正式知识库。分配资源时记录所属 run 和 Compose project；成功、失败和中断均回收本轮子进程、容器、卷、网络、应用镜像标签与临时私有目录。清理失败保留恢复配置，并在任务中写明遗留资源及恢复命令：

```sh
node tests/service/runtime.mjs cleanup <run-id>
```

不要清理其他任务资源、用户浏览器资料或正式 `.local/knowledge`。保留失败诊断和少量必要证据即可，不要求全仓源码/环境指纹锁定或单独证据审计门禁。当前检查不覆盖移动端或公网部署。

## 补充验证方法

按上方项目命令矩阵选择检查并说明依据。缺陷修复从原输入复现并对照前后行为；模块变化覆盖相关调用方与全局守卫。权限或迁移还须核对绕过与拒绝、旧数据、部分失败和恢复。静态文档核对内容、链接和重复规则，有布局要求时查看实际渲染。定向验证后按新变化、失败或剩余风险决定是否扩大，各项必需检查仍按项目矩阵执行。

### 回归测试证明行为

- 夹具来自真实输入或忠实的最小复现，覆盖缺失字段、空值、截断、异常和边界；敏感数据先脱敏。
- 断言用户或调用方需要的行为。精确字节只有在协议、序列化或兼容要求依赖它时才作为约束。
- 可稳定复现且适合自动化的行为缺陷，优先新增或补充已有回归测试。在安全可执行时，用同一测试运行旧实现或隔离撤销修复逻辑，确认因原行为失败，再验证修复后通过。编译失败、测试跳过、环境未启动均不算旧实现反证。
- 文档、低影响静态缺陷或不适合自动化的问题，可使用内容核对或手工行为对照。无法安全执行旧实现时，记录替代证据和验证缺口，不能标为“旧实现已失败”。修改原实现的反证实验在隔离副本进行，避免干扰他人工作。
- 测试名宣称的保证应能由受控反例打破。权限、清理、取消与等待类测试需要证明相应路径真的发生。

### 隔离环境与资源生命周期

常规自动测试使用受控本地依赖和锁定版本，阻止意外访问真实服务。真实集成检查单独标明，确认授权、费用和数据副作用后在隔离环境执行；模拟成功不能替代真实兼容结论。

测试写入专用临时配置、数据库或数据目录；通过工具支持的配置入口隔离，避免修改真实用户配置。需要调整进程环境时在测试子进程局部设置，勿在共享 shell 重定义系统变量。可复用的依赖缓存保持稳定，核对缓存路径后再清理临时目录。

- 每个测试拥有自己的端口、文件、存储命名空间和伪服务；浏览器连接的服务应能确认来自当前工作树。固定端口上的健康响应不代表它就是本次代码。
- 测试启动的任务、计时器、线程、连接、流和子进程在结束前取消并等待退出，失败路径也执行清理。
- 测试修改共享文件时保存原字节，恢复后检查写入成功；优先使用隔离副本。
- 伪服务的并发处理同样需要同步。计数与记录只统计本测试拥有的请求，避免后台刷新混入断言。
- 完整测试争用资源时协调并发或错开运行，不把资源耗尽当作业务失败，也不因猜测负载就忽略红灯。

### 时间、状态与不稳定测试

- 等待最终要断言的状态或事件，以截止时间限制等待；不要以固定睡眠或前一步已完成推断最终状态。
- 时钟、时区和调度尽量可注入。测试修改进程级全局时间设置会污染并发测试，优先使用局部依赖。
- 时间边界、日期和分类阈值分别覆盖边界行为；普通路径夹具远离无关阈值，留出执行余量。
- 注入延迟、阻塞或乱序重现时序问题，检查所有时间假设。一次重跑变绿不能解释原因。
- 排查时核对失败环境的运行时、依赖、平台与负载，搜索已有问题并读完最新讨论，优先评估已有补丁。
- 保留完整日志直至每个失败归因。已知失败记录复现、影响、跟进位置和处理状态，不能隐去或计为通过。

### 完整性与平台边界

按项目现有入口运行格式、静态检查、构建、模块测试和必要集成检查。新增路由、配置字段、依赖或包级初始化时，查找列举它们的全局守卫，不能只运行新函数的测试。

确认测试被发现且断言执行；零测试、空扫描、过滤漏项和提前退出要单独报告。命令管道保留真实失败退出码，不能只看截断日志或最后一个工具成功。

跨平台构建不等于在目标系统运行测试；测试文件是否编译也需确认。一个浏览器引擎的自动化结果不等于所有宿主嵌入版本、桌面壳或真实设备均通过。只对实际覆盖的环境给出结论。

界面验证包括用户交互、键盘与焦点、滚动、响应式布局、错误和空状态；支持多语言时核对文案与占位符。输入框按实际输入法的组合事件验证，不能只用直接赋值覆盖全部输入行为。

性能检查使用相同环境与可比较输入，关注变化趋势、最大合理输入及热路径调用频率；采样噪声或单次耗时不能独立证明改进。

### 记录结果

在实际使用的交付记录中关联输入、环境、命令、结果和证据位置，明确区分通过、失败、未运行、跳过与取消。实际输入变化后重新核对覆盖，不能借用其他工作树、旧基线或后续版本的结果。
