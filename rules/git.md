# Git 与并行协作

- 开始编辑前检查工作树。已有改动属于用户；不得用 reset、checkout 或清理命令覆盖。
- 一个任务对应一个可回退的逻辑提交，包含实现、相关测试和直接关联的文档。默认新分支使用 `codex/` 前缀；小范围初始化可在当前分支完成。
- 并行工作先约定文件所有权；共享文件由一位负责人合并。长任务或互相冲突的改动使用独立 worktree。
- 验证通过后审查 `git diff` 和 `git diff --cached`，按显式文件路径或代码块暂存；不使用全量暂存夹带未知修改。
- 提交信息使用 `type(scope): 简洁说明`，常用类型为 `feat`、`fix`、`docs`、`test`、`ci`、`chore`。本地提交属于开发交付；推送、发布、重写历史或删除工作树按用户明确授权执行。
- 只读任务不创建空提交。提交失败时保留已验证成果并报告原因，不伪称完成提交。

本仓库目前没有强制 Git Hook 或提交信息校验器；上述为协作约定。自动化检查范围以 [CI](../.github/workflows/check.yml) 为准。
